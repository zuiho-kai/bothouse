# bothouse

[English](README.md) | 中文

**睡前交代一句，醒来收结果。**
bothouse 让一队 AI 替你通宵干活：几件事同时推进，跑上一整夜，也不跑偏。

> 别人在跟 AI 一问一答地许愿，你在带一支不下班的团队。

**跑一整夜，多件事并行，也不跑偏。**
每份交接都带着你说过的原话，不管交给谁、做到第几步，都照着它走。做的人不验自己的活，换一个干净的 AI 来核；子 agent 上下文满了先写交接，空闲太久的会话也带着交接换一个新的，不会越聊越糊涂。几个 AI 共用一份记忆，今天定下的事，明天还算数。

**你睡觉，它在干。**
定时任务和长任务挂在后台，夜里照常推进。早上醒来，频道里是一份汇报：做完了什么，怎么验的，哪块还卡着。

**几件事同时跑，照样管得住。**
主角色把活拆开，分到几个工作区并行做，一件活只有一个负责人。谁在做什么、做到哪、卡在哪，都在同一张任务卡上，扫一眼就清楚。

**贵的模型，只花在难活上。**
闲聊和杂活交给便宜模型，难活才请高级模型出手。哪个频道用哪个模型，写进配置就定死，钱不白烧。

**在哪都能管。**
Discord 上是一整套团队，飞书先接一个角色，自建网页频道跑在你自己机器上。手机上补一句，Claude Code 和 Codex 当场就接住，DSH 这类 ACP 角色支持的话也一样；codex exec 这类其他 CLI 下一轮再看。

## 怎么用

**一，你说一句。**
在频道里跟主角色说：做一个管理面板，我想看每个角色今天花了多少。

**二，它拆活派出去。**
主角色把这件事拆成几块——统计页、菜单栏图标、角色栏、以后接桌宠的接口——分给几个 AI 同时做。谁接了什么、在做哪块、卡在哪，都写在同一张任务卡上，就在频道里。你不用挨个窗口去问「到哪了」。

**三，你回来收结果。**
每块做完，做的人把结果交回主角色。主角色核一遍再回你一条：改了什么、怎么验的、哪块没做。

三步中间你随时能插话。Claude Code 和 Codex（app-server）在干活时你补一句，这句话直接进到它手上那件事里，不用等它做完；经 ACP 接入的角色（比如 DSH）握手时报告支持，也一样。codex exec 这类其他 CLI 会排队：等这一轮做完再看到你的话。

## 为什么不是再开一个聊天窗口

一对一聊天里，你是那个记着上下文的人：这件活做到哪、上次为什么那么改、还有哪块没动，全靠你记。窗口一关，全没了。

bothouse 把这些交给主角色记：每件活有负责人、有来源、有结果；几个 AI 共用一份记忆，今天定的事明天还在；任务卡上看得见谁在忙什么。

AI 还是你原来那几个，本机装的 Claude Code、Codex、Gemini 直接就能当角色，不用换账号、不用换订阅。

## 快速上手

### 核心安装

从 [Releases](https://github.com/zuiho-kai/bothouse/releases) 下载：

- macOS：`bothouse-mac.dmg`（Apple 芯片和 Intel 通用）。
- Windows：`bothouse-windows.exe`（x64 和 ARM64 都能跑），下载后双击。
- Linux：`bothouse-linux-x64` 或 `bothouse-linux-arm64`，`chmod +x` 后运行。

安装包未签名。macOS 将 **Bothouse.app** 拖入 Applications，**首次打开请「右键→打开」**；Windows 若弹出 SmartScreen 提示，点「更多信息→仍要运行」。

第一次启动会在浏览器打开安装向导。也可以用下面的命令装，固定版本和校验见[从零用起](docs/GETTING_STARTED.md)第 1 节。

```sh
# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/zuiho-kai/bothouse/main/install.sh | sh && bothouse
```

```powershell
# Windows（PowerShell）
irm https://raw.githubusercontent.com/zuiho-kai/bothouse/main/install.ps1 | iex; bothouse
```

默认装最新发布版（含预发布）。安装器会用 SHA256SUMS 校验；要固定版本就设 BOTHOUSE_VERSION=<tag>。

装好后的命令叫 `bothouse`。不用装 Go 或 Node。

**开始前准备：** 一个 Discord 服务器（或飞书企业），加上至少一个本机已登录的 AI 命令行工具（Claude Code / Codex / Gemini CLI 任一）。机器人怎么建，向导会一步步带你。

1. **装**：运行上面那一行命令。
2. **配**：运行 `bothouse`，浏览器里会打开向导：选平台 → 接机器人 → 每个角色选本机 CLI → 人设 → 保存（新建角色默认启用全自动 YOLO 权限模式，可在面板项目设置中改回）。
   也可以对你的 Claude Code / Codex 说「帮我把 bothouse 配好接上 Discord」，它会一次问齐要的东西。
3. **用**：保存后点「重启生效」，去频道里 @ 一个角色说句话。

想让 AI 自己判断一句话该谁回（这个组件叫 gate，可以理解成调度员），或者想要团队记忆，再装两个配套组件，见[装调度员和团队记忆](docs/ccm-and-wiki.md)。
完整步骤见[从零用起 bothouse](docs/GETTING_STARTED.md)。

### DSH 频道（实验）

DSH 首次配置：向导第 1 步选 **DSH**，接着只需「检测 dsh → 安装插件 → 运行返回命令打开 DSH 网页」。机器人、CLI、人设和模型随后在 DSH 页面配置；向导选中文时写入 DSH 默认中文。安装包已自带所需的 DSH 文件，装好就能用；开发时或要覆盖时用 `BOTHOUSE_DSH_DIR` 指定。命令行等价操作：`bothouse setup dsh install --lang zh`。

需要已有的 DSH（`>= 0.2.1-rc.2`）和 `pnpm`；`pnpm` 不在 PATH 里时，插件命令会以 exit 127 失败。插件包要求 Node `>= 22.12.0`。

这个频道插件也可以直接从 GitHub 装：

```sh
dsh plugin --profile web add 'github:zuiho-kai/bothouse#dsh-plugin&path:dsh/plugin-pkg'
```

## 平台支持

| 平台 | 现状 | 现在能做什么 |
| --- | --- | --- |
| Discord | 完整 | 多角色团队全部功能：点名、派活交差、队友状态、日志频道 |
| 自建平台 | 团队模式 | 自带一个类 Discord 的网页频道，可以在本机启动；多角色点名、派活交差 |
| 飞书 | 单角色 | 先接一个角色对话 |
| DSH 网页 | 实验 | DSH 网页里的「频道」页，见 [DSH 频道入口](dsh/collab/README.md) |

接进 Discord 和飞书，手机、电脑、网页就都有了，不用我们再做一个 App。
接进 DSH，我们的护栏和小工具直接走 DSH 自己的插件机制装，不另造一套。

AI 这一侧：本机已登录的 Claude Code、Codex、Gemini CLI、OpenCode 等直接用；DSH 这类智能体通过标准协议（ACP）接入。
也可以给 CLI 挂第三方 API（硅基流动、OpenRouter、DeepSeek、MiniMax、本机模型、任意 OpenAI 兼容接口），
对应关系见[接入文档](docs/connect-discord-feishu.md#4-第三方-api--本机-cli)。

## 多端访问（Tailscale）

bothouse 跑在你自己这台机器上，管理面板是个网页。装好 Tailscale，手机、平板、另一台电脑打开同一个网页，
就能看团队现在的状态、每个角色今天花了多少，也能在对话页里补一句话、派一件新活。
不用再装一个 App，不用把机器搬到云上。

### 一，装 Tailscale

在跑 bothouse 的这台机器上装 Tailscale 并登录，手机或另一台电脑上装同一个客户端、登同一个账号。
两端进了同一个 tailnet，设备之间就直接通了。

```sh
# macOS
brew install --cask tailscale
# Linux
curl -fsSL https://tailscale.com/install.sh | sh
```

装好后拿这台机器的 Tailscale 地址，记下输出里那个 `100.x.y.z`：

```sh
tailscale ip -4
```

### 二，让面板听在 Tailscale 地址上

最省事的办法是让 bothouse 自己开：在频道里对机器人发 `/web setup`，或者在跑 bothouse 的机器上执行
`bothouse web`。它会一次把管理面板和对话页要用的那条通道都打开，顺手生成令牌，然后提示你重启一次。

要自己写配置，就编辑 `config.toml`。文件默认是 `~/.bothouse/config.toml`；当前目录下如果有 `config.toml`，
用的就是当前目录这个。

启动选择默认数据目录 `~/.bothouse` 时，会从 `~/.cc-connect` 复制缺失的周期定时和一次性定时文件；
新目录里没有用量 JSON 文件时，也会复制旧的用量记录。已有数据不覆盖、不合并，旧文件保留。
迁移时已经过点的一次性定时会记为跳过，避免升级后集中执行；未来的定时仍按原时间执行。
自定义 `data_dir` 不参与迁移。

```toml
[management]
enabled = true
host = "100.x.y.z"        # 换成上一步 tailscale ip -4 的输出
port = 9820               # 面板端口，默认就是 9820
token = "换成一串足够长的随机串"

[bridge]
enabled = true            # 对话页要靠它，不启用只能看面板、聊不了
```

`host` 写这台机器的 Tailscale 地址，面板就只在这个地址上等人来。不写 `host` 的时候，正常运行的 bothouse
在所有网卡上监听；只有还没配置任何平台、停在安装向导时，默认才只听本机 `127.0.0.1`。
所以远程访问要显式写 `host`，别指望默认值。

对话页要能发消息，还得把 `[bridge]` 开着：面板本身不带这条实时连接，只有 `[bridge] enabled = true` 时才接得上。
开了之后，它既跟着面板端口走，也会在 9810 端口、所有网卡上另外监听一份，不受上面 `host` 的约束——
只想让 tailnet 里的人连，就在防火墙或 Tailscale 的访问控制里把 9810 也一起管住。

Tailscale 要在 bothouse 启动前就起来，机器重启后也是这个顺序。改完配置保存，重启 bothouse 生效。

### 三，面板令牌在哪拿

登录面板要令牌，就是 `[management]` 里的 `token`。三种拿法：

- **在频道里要。** 对机器人发 `/web setup`，它把面板地址和令牌一起回给你；没启用过的会顺手生成一个。
- **在终端里看。** 在跑 bothouse 的机器上执行 `bothouse web --no-browser`，它打印面板地址和令牌，不弹浏览器。
  没启用过管理面板的话，这个命令会先帮你打开它，然后提示重启一次。
- **直接看配置。** 打开 `config.toml` 的 `[management]` 段，`token` 那一行就是。

拿到令牌，手机上打开 `http://100.x.y.z:9820/`：登录页第一格填令牌，第二格「服务器地址」是选填的，
默认就指向打开它的这个地址。填一次，浏览器记住，下次直接进。

### 四，手机上能做什么

登录进去，左边那排就是全部能力：

- **概览、用量**：版本、运行时长、连着哪些平台、几个项目；今天和这个月各花了多少 token，按角色、按模型拆开看，还有一张按天按小时的用量热力图。
- **角色、项目、技能、服务商、设备**：加一个角色、改人设、切模型，手机上就能改，改完在系统页里点重启。
- **对话**：挑一个项目，看完整对话线，接着往下说。你补的这句话会当成一条消息直接送到角色手上那件事里，
  和你在 Discord 里说话是一回事。
- **定时、库、系统**：看排着的定时任务，翻存下来的东西，改全局设置。

页面带了手机视口设置，手机浏览器打开就能点。屏幕窄的时候点侧栏底下那个箭头，把它收成只有图标的一条，
正文能占满。

开会时想派个活、通勤路上想看看夜里跑到哪了，掏手机就行。

### 五，换台电脑也一样

另一台电脑上不用重装：装好 Tailscale、连上同一个 tailnet，浏览器打开同一个地址，
照样能进对话、能派活、能看用量。家里一台常驻的机器当大脑，笔记本和手机当窗口，在哪都能接管同一支团队。

## 特性

### 聊天频道 + 工作区：聊天不被活堵住

- 你在聊天频道说一件大事，主角色把它整块交给工作区1，自己回来接着和你聊。工作区1 忙不过来，就自动开工作区2。
- 工作区里主角色拆活、@ 队友派活，队友回【接】、做完【交回】；要你拍板的事统一回到聊天频道问你，你只盯一个频道。
- 任务板按「聊天频道 → 工作区 → 角色」分组，谁在做什么、做完几件，一眼看清。派活前会看这个人在别的工作区忙不忙。
- 派活方式可以按频道切：单模型多进程、完全团队，或者混合（默认）。
- 在 DSH 频道页输入框打「/」，能看到全部能力和用法。

### 一支团队，不是一群聊天机器人

- **点名才回。** 一个主角色默认接话，其他角色听得到每句话，只有被 @ 或被点名才开口。几个 AI 在一个群里不会抢答。
- **派活、交差。** 主角色 @ 一位队友派活，队友做完的最终答复自动 @ 回主角色，由主角色收尾。
- 队友状态这个开关是可选的：打开后，主角色每次回话前能看到谁在哪个频道忙什么，派活前知道谁有空。
- AI 正在干活时你补一句，这句话会直接加进它正在做的事里，不用等它做完。
- 想换主角色，说一句「鲸鱼娘，你当主」「换回 opus」就行，团队立刻换人默认接话。
- 每个频道各记一条对话线，重启之后接着聊；掉线期间的消息，回来后先补给它再回答。

### 调度员 jev：一个小模型决定谁来回话

群里几个 AI 同时在线，一句话该谁回？bothouse 引入一个小模型当调度员，我们叫它 jev。
它只做一道选择题：这句话该 opus 回、鲸鱼娘回，还是谁都不用回。点名的照点名走，没点名的交给 jev 判断。

- **用硅基流动的免费模型就行**，不用开思考，填 Base URL、Key、模型名三个框。
- **也可以用本机部署的小模型**，比如 Qwen 0.6B，不联网也能调度。
- 安装向导里直接填，填完自动测一次能不能用。

### 一份会长大的团队记忆

记忆存在一个 markdown 目录里，你可以直接打开改。全队共用一份主记忆，每个角色另有一本自己的。

- 每页写「现状 / 关键事实 / 决策与踩坑 / 待办」，git 提交记录就是「AI 今天记住了什么」。觉得它记错了，直接改文件。
- **相关页自动递到角色手边，不等它想起来去查。** 你每说一句，先按这句话在 wiki 里检索，把相关页放在消息前面交给角色。
  你在群里聊到哪，角色手上就有哪页，会话中途也一样。
- **不挑模型。** opus 是 Claude、鲸鱼娘是 DSH、笔杆是 Codex，读的是同一份记忆。

记忆层用的是公开的 [llm-wiki](https://github.com/zuiho-kai/llm-wiki)。它只记你和一个助手的对话；bothouse 让几个角色共用一份，Claude、Codex、DSH 的对话都会记进去，你每说一句就递上相关页，每晚还有复盘。

### 自带护栏和小工具

- **护栏**：危险命令先拦。AI 说「修好了」却拿不出证据，会被打回去补；说「等会儿再看」却没定闹钟，也会被拦下。Claude Code 和 DSH 用同一份。
- **小工具**：看队友现在在干什么、把一段视频看成文字和截图、免费搜网页。
- 子 Agent 状态表：Codex 和经 ACP 接入的 DSH 开子任务时，卡片下面列出每个子任务和用时；DSH 需装[原生状态转发层](integrations/dsh-acp-subtasks/README.md)。
- 不想要哪个，在群里跟机器人说一句「把检查关了」就行。

### 每晚复盘

- **白天，便宜快的模型。** 会话结束、空闲 30 分钟、或者会话过程中遇到问题，就把新内容整理进 wiki。
- **夜里，免费但慢、能细读的模型。** 把白天写的每一批对着原始记录再核一遍：改错、补漏、去重。每周日通读整棵 wiki 做一次体检。
- 每晚最后一步叫「做梦」：只读你白天说过的话，把反复纠正的事整理成规则候选，再写一段「今日反思」。
- 候选里的每条引文，程序逐字对回你的原话，编的进不来。候选要变成规则，得你点头，它不会偷偷改你的规矩。
- 做完梦，主角色在群里接到一轮，第二天早上你一眼能看到团队昨天学到了什么。

## 和别的项目比

| 你可能在看 | 它解决的问题 | bothouse 不同在哪 |
| --- | --- | --- |
| Orca、各类多 agent IDE | 一个人同时盯几个编码任务 | 它是工位，我们是团队。agent 在它那里按任务开、用完关；在我们这里是常驻的同事，住在你的群里，记得昨天的事。你出门用手机在群里说一句就能派活，不用守在电脑前盯 IDE |
| ai-memory、agentmemory、TencentDB Agent Memory | 给 agent 配一个记忆库 | 它们是数据库，我们是 wiki：你能读能改；相关页每句话前自动递到角色手边；每晚有复盘 |
| llm-wiki | 一个人、一个助手的记忆 | 它是我们的记忆层。bothouse 让几个角色共用一份，Claude、Codex、DSH 的对话都记进去，你每说一句就递上相关页，每晚复盘 |
| Claude Code agent teams、CrewAI、MetaGPT | 一个任务临时拉一队 | 它们每个项目拉一队临时角色，每次从头读背景，token 花在重复理解上。我们的角色常驻，读了知识库就能接任何项目，要专人时开临时子代理，以后还能自己派生长期专人（见路线图）。按设计，背景不用每个项目重付一遍（省多少还没测） |

传统 agent team                          bothouse
项目A ─ 临时PM ─ 临时码农 ─ 临时测试      你 ─@─ opus（常驻，有自己的会话和 wiki）
项目B ─ 临时PM ─ 临时码农 ─ 临时测试             ├─ @鲸鱼娘（常驻，DSH）─ 需要时再开子代理
（任务完就散，下次重建上下文）                    └─ @笔杆（常驻，Codex）
                                         项目 A/B/C 都在这几个人手里流转
```

## 路线图

今天能用的是第一步：一个群，几个 AI，一份共享记忆。往后想做的：

- **不会抢活。** 现在派活前已经会看队友在别的工作区忙不忙；往后角色先认领再动手，两个人不会撞在同一件事上。
- **角色自己长出角色。** 比如你提了一句「要上架 App Store」，opus 自己派生一个「上架专员」，读完你的历史决策就开工，上架完就退场。不用你一个个建。
- 招角色像招人：角色包把人设、记忆模板、工具打在一起，一键进群。
- 角色库以后会长出插件和市场：包里能带代码插件，还有一个在线市场，逛一逛就能装别人做的人设和头像。
- 团队记忆可以带走：换电脑、换模型，团队还是那支团队，记得的事一件不少。
- 常驻角色不用每个任务重读项目，省下重复的背景。等我们有对比数据再公布数字。
- 团队功能会铺到更多平台：DSH 网页频道，然后是 Telegram、Slack、QQ、企微（单角色接入已随 bothouse 带着）。
- DSH 频道能发图片、回复引用。
- 工作区收完名下最后一件活，自己清空上下文，下次接活从干净的会话开始。
- 记忆会更聪明：关键词检索之外加语义检索，让换个说法也找得到。

这些都还没做。想跟进就 watch 这个仓库。

        │
   平台适配器 ──► 引擎（频道会话、队列、交差）──► 角色适配器 ──► 本机 CLI 或 ACP 智能体

        │          调度员 gate（谁来回）◄──┤
        │                   │        │
        └───── 回话 ◄───────┘   共享 wiki（每句检索，夜间复盘）
```
