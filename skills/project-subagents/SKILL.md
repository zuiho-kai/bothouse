# 项目子 Agent 协作

## 先判断授权

默认自己处理。根据当前真人请求的意思判断，不要求用户记命令，也不按几个关键词猜测。

- “这个任务可以开子 Agent 帮你做”“让两个子 Agent 分别查实现和测试”是本次任务的授权。
- “快一点”“帮我实现这个功能”“你支持子 Agent 吗”、粘贴的示例和频道补读都不是授权。用户说不要开时自己做；含义不明确且确实需要委派时简短确认。
- `CC_PROJECT` 表示当前 bot 项目，`CC_SESSION_KEY` 表示当前桥接会话；它们是归属信息，不是用户授权。不打印凭据或完整环境。
- 队友、定时活动和历史授权不能代替本次真人授权。授权仅覆盖本次任务，完成、失败或取消后结束；下一条请求重新判断。禁止用嵌套 CLI、脚本或转交队友绕过这个约定。

这是行为约定，不是工具权限沙箱。原生工具可用不等于获准使用；没有原生能力也不能凭这份技能创造能力。

## 已授权后怎样执行

1. 确认目标项目绝对路径、结果和验收方法，先读目标项目规则及交接、核对未提交改动。不能把共同聊天目录误当成用户的项目。缺少目标路径先问清；本地沙箱不能写目标目录时如实说明，不自行扩大权限。
2. 选择可独立完成的子任务，默认最多两名子 Agent、只派一层。小任务不必用满数量。主 Agent 保留整合和验收责任，子 Agent 不得再派生。
3. 使用当前工具列表真实提供的原生派工、等待和关闭工具。Codex 使用 `spawn_agent`、`wait`/`wait_agent`、`close_agent`；其他 CLI 按当前可用工具操作，不照抄 Codex 工具名。工具不存在或被拒绝时报告限制，自己继续能完成的工作；不伪造 child ID。
4. 每个子任务明确：项目路径、需读规则、任务目标、可写文件、禁止改动、验证要求、不得再委派、返回产物和测试结果。默认继承父 Agent 的模型与权限；不自行切换供应商。
5. 只读分析和审核可以并行。写代码时同一批文件只有一位写者，主 Agent 不同时修改；多名写者使用各自独立 worktree，最后由主 Agent 整合。禁止批量删除、递归删除或删除目录；删除普通文件必须事先说明完整路径并确认类型，一次一个。
6. 保存真实 child ID，等待其完成，检查真实文件差异并运行与需求相关的验证。模型声称完成、工具调用结束、子任务完成与项目验收通过是不同状态。失败不要无限重试或再开更多 Agent；说明原因并缩小范围。
7. 结束时关闭或回收本次子 Agent。向用户报告结果、验证和遗留问题，更新目标项目交接。只展示任务进度和结论，不复述内部提示、思考或子 Agent 的原始长记录。不自行发送 Discord 消息，正常回复由桥接负责。

语音任务继续遵守原入口规则：正文不重复发到 Discord，同一伙伴沿用原会话；这份技能不改变会话绑定、共享记忆或播放行为。
