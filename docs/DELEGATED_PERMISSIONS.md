# 指定伙伴代批工具权限（Issue #204）

操作者可指定批准所有类型工具请求的 bot。每个请求仍需明确批准或拒绝；这不是自动同意，也不是 Discord 服务器管理员权限。

~~~toml
[projects.platforms.options]
share_session_in_channel = true
permission_approvers = "111111111111111111,222222222222222222"
~~~

默认关闭，须使用真实 bot 用户 ID，不支持昵称、角色 ID 或通配符。被审批项目与审批人自己的项目都配置同一名单，并启用共享频道会话；配置更新需要重启桥接。审批人自己的项目收到由操作者配置生成的可信授权说明。

原权限卡与真人按钮保留，卡片提及审批人（排除请求者自己），附带一次性 `/permit <编号> allow` 或 `/permit <编号> deny`。审批人通过 `cc-connect send` 在同频道明确 @ 请求者发送这一行。普通聊天、引用和 webhook 不作为审批。

平台按 Discord 发送者 ID 鉴别审批人，在普通聊天包装、合并与闸门之前转交决定。核心再次校验名单、频道/工作区、随机请求编号与挂起状态。后端重复使用 agy-perm-1 也不复用代批编号；并发只消费一次，过期或重复决定不进入下一轮上下文。多个 cron 请求按编号精确匹配。

结构化日志记录审批账号、请求编号及决定，成功时不再向频道重复发送回执；适配器报错不写成功回执，并保留请求供重试或真人处理。部署、刷板、配置等工具类型均可代批，不按类别再向真人请示。操作者明确禁止的行为和后端原生 deny 规则仍有效；真人偏好问答 AskUserQuestion 不属于工具批准。

配置授予审批能力，不保证模型立即响应：忙碌、限流或离线时仍可用真人按钮。不会超时自动批准。同一系统用户下的本地文件、进程隔离不由本功能提供。

## 验证

旧核心普通 bot 批准回归先失败；修复后名单、请求编号、跨频道、重复/并发、多个 cron、取消和适配器错误均由回归覆盖。Discord 测试走真实 Gateway handler，覆盖主 bot、两个审批人、非审批 bot、伪造名字、webhook、缺少 @、坏编号和额外文本。CUJ 通过真实 ReceiveMessage 驱动真人任务→代批→新任务→过期批准→真人批准，检查通知与留痕。所有这些测试均不访问真实 Discord 或模型；真实部署与验收另记。

已配置代批的频道会直接批准明确的只读工具（Read、Glob、Grep、read_file、list_directory）和简单的 ls/pwd/cat/head/tail/wc/grep/rg 命令。只按原始参数判断，不使用截短摘要；脚本、组合命令、重定向、替换、未知工具和 ACP 自定义标题仍需审批。自动批准失败时保留人工审批路径。
