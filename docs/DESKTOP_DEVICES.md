# 电脑固定设备入口（Issue #43）

先验证“一位伙伴对应一台设备”的软件行为，再接两台实体终端。输入是设备页面确认的文字或录音转写，输出只属于该设备绑定的伙伴；反馈包括思考、分块播放、完整播放、停止与错误。电脑继续承担模型、ASR、TTS和共享记忆。

## 本次实现

- 首页展示明确配置的设备；每个 `/device/<device_id>` 只有一个固定伙伴，服务端拒绝改成别的 project。
- 复用 PR #47 的 DeviceRegistry/配置格式，以及现有 VoiceService、分块播放器和共享记录。一次输入只走一条 `/input` 链路，不再同时调用 DeviceRouter.converse，避免双重投递。
- 服务端从接纳开始持有整个房间，直到生成收尾且持有页面确认播放完成/停止/失败。**合成结束不等于播完**。另一台忙时得到409，输入保留，不排队、不自动重试。
- 原会话在首次核对时固定；发送前、桥接接纳和返回时继续核对。改变绑定时拒绝，不能悄悄创建新会话。首版要求设备显式绑定同一个实例频道。
- 每个页面使用新的 client UUID，音频地址包含设备、轮次和该页面归属。其他设备、重复窗口、刷新后的新页面不能获取或重播旧音频。已完成/停止的音频不再提供重播，以免与下一位重叠。
- 停止先在浏览器暂停，再通知服务端。尚未送出的输入不再送；已经送达的 CLI 请求继续收尾，占位保留，迟到正文可归档但不会重新合成/播放。停止发生于分块合成中时，后续块不再发布。
- 共享 submitted/finished/playback 记录带 device_id/audio_target。语音使用原有隔离输出通道，不调用 Discord 发消息接口。同伙伴继续原会话，其他伙伴仍按需查共享记录。

## 启动与人工检查

先按 [独立实例配置](INSTANCE_SETUP.md) 准备 voice 配置和角色名单；设备格式参考 `companion/examples/device-bindings.json`，替换占位频道，保证设备与 voice 配置的 session_key 完全一致。

~~~sh
cd companion
uv run python -m voice.device_server \
  --config /absolute/path/to/device-voice-config.json \
  --roles /absolute/path/to/roles.json \
  --devices /absolute/path/to/device-bindings.json
~~~

三份文件与端口必须显式指定；voice 数据目录应独立，只有经过确认的桥接原会话和共享记忆目录共用。使用实际语音须安装语音额外依赖并提供本地模型，基础 uv 环境只承担离线测试。不会初始化旧配置、下载模型或启动 Discord bot。

1. 打开该端口的首页，分别打开 G哥和 Cursor 的设备入口。并排使用两个窗口；隐藏页面会停止该页面本轮，避免后台突然说话。
2. 向 G哥发送短问题。确认只有 G哥收到、只有 G哥页面播放，Cursor 保持安静。
3. G哥播放期间向 Cursor 提交：提示正在忙，保留输入；G哥完整播完后再提交，Cursor 才开始。
4. 在生成和播放中分别按“停止本轮”。声音立即停，迟到音频不恢复；后台请求仍在结束时，下一条暂不接纳。
5. 刷新或重复打开同一设备。新页面不能接管或自动重播旧回答。丢失停止回执时保持占位，需原页面确认停止，或确认设备已静音、后台任务已收尾后重启这个独立入口。
6. 真人按住录音、确认转写、听回答。自动浏览器使用文字和测试 WAV，不代替这一步，也不证明实体扬声器已经播放。

不要同时在旧8793与设备入口安排有声对话：房间占位只覆盖本设备服务进程，尚未提供跨服务/跨进程音频锁。8793普通页与讨论页的行为保持。

## 当前边界

这是 localhost 电脑模拟，设备 UUID/client UUID 是单用户页面归属，不是联网硬件认证。没有Wi-Fi传输、固件、独立音频输出、设备状态灯、自动接话或跨房间调度。#42 需要再定义设备凭据、连接世代、失联确认与音频协议；#33 负责何时允许其他伙伴加入。

未收到可信停止/播完回执时，不用超时猜测设备已静音。不能检测被修改的客户端是否真的播放，也不保证用户听见。页面崩溃或停止回执丢失可能需要人工恢复；本进程最多保留200轮请求防重记录，达到上限要求空闲时重启。重启不会恢复旧音频或自动重发。

本次软件PR不关闭 #43，不等于真实双设备、真人麦克风或部署验收。生产8793/8787与Go桥接没有因本次开发而重启；上线另留独立记录。
