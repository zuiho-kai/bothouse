# 伙伴身份与重复授权：Issue #172

## 2026-10-20 现场与边界

真人报告大豆包自称 C酱，同轮出现 `antigravity: unknown permission request "agy-perm-1"`；肥鱼再次出现 `PUBLIC_ANSWER_UNAVAILABLE`。三个信号不能当成同一个故障。

- 大豆包本机配置的 team_name 已是“大豆包”。桥接没有每次明确注入自身名称，队友缓冲又会丢失作者；这是可以复现的输入缺口，但不是对模型内部生成过程的证明。
- 15:59:32 两条响应到达；权限适配器已消费请求，而核心等待平台回执后才清 pending，第二次响应因请求不存在报错；15:59:34 原请求完成解除等待。隔离测试用真实核心、单次消费的后端边界和阻塞的平台回执重现相同错误。
- 肥鱼原生记录显示三次工具结果均 isError=false，末步答复失败；不能由工具未报错推断任务完成。原记录只有统一失败码，没有可恢复的细分原因，不能断言格式、超时或供应商故障。
- 肥鱼插件的 Cordis warn 没有可靠导出至 ACP stderr；安装运行时的默认日志缓冲也过滤了该级别。此修复补足可观察性，不声称修好了尚未定位的答复生成故障。

## 修复

有 team 配置的项目，每次实际投递都从本地配置取得自身名称，声明这是伙伴称呼，不改变真实模型/供应商。首次、续接、排队、严格语音、进行中插入及项目转交均带身份；压缩指令保持原生协议。关闭子 Agent 授权说明不会关闭身份。队友缓冲使用带作者的 JSON 引用，保留原正文供 gate 分类，提示中区分队友报告与自己核实的结果。

权限响应在调用适配器前原子认领 pending；平台回执未返回时，重复响应直接消费而不再次调用后端。旧请求完成只清理自身 pending，不清掉已替换的新请求。允许、拒绝、全允许和问答都经过同一认领边界；保留真正的后端错误。

DSH 诊断直接写 ACP stderr，由桥接已有日志管道保存；只包含固定 stage、attempt、cause，既不输出原始异常/模型内容，也不重试原任务。

## 验证与限制

- 修前：身份 CUJ、队友作者回归和重复授权回归均失败；后者精确报 unknown permission request 并记录两次后端响应。真实安装 DSH middleware 测试也因 stderr 诊断为零失败。
- 修后：身份首次/排队/续接、严格语音/插入、引用作者、四种权限响应的目标测试及20次 race 重复通过。DSH 真实安装离线契约37项通过、0跳过；CUJ和目标 vet通过。
- 全量检查第一次失败于既有测试仍要求队友缓冲等于无作者裸正文；改为校验引用作者及原文，同时保留“不触发机器人回合”的断言。后续全量结果以 PR/交接记录为准。
- 身份提示是行为约定，离线测试证明投递边界，不能保证任意模型绝不串台。旧对话不改写，原任务不重跑；实际频道验收与部署另记。
- 大豆包后续 `stream turn failed (ERROR)` 已另按真人授权交子 Agent 追查，不能用本页的重复授权修复宣称已解决。
