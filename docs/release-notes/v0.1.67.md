## Highlights

- **Interrupting a long subagent gets an answer.** When you send a message while the main session waits on a foreground subagent, the bridge now moves that subagent to the background (Claude Code `background_tasks`), so the role reads your message and answers right away; the subagent keeps running and reports when done. If the backend cannot do that, you get one line saying which subagent the turn is waiting on and for how long, instead of a bare "inserted" receipt (#1595).
- **Claude CLI team members can switch models.** The team API creates `cli: "claude"` members, and both member PATCH routes accept a Claude model ID; the choice is applied through ACP `session/set_model` before the next prompt, `model: null` restores the default, and a failed switch stops the turn with an error (#1593, thanks @jsk11231).
- **Nightly fix bundle.** Role wiki runs get the scheduler's remaining time and the nightly export stops waiting on the ingest lock at its budget; setup keeps embedded DSH data in its own directory; DSH defaults to native DeepSeek and reuses the chosen model and key; a gateway must have its own credentials; plugin installs are confirmed before success is reported; messages sent out are kept for the next turn's context; a failed QQ save no longer shows "connected"; `dsh web` takeover is stricter (#1594, thanks @Zssan12).

## Fixes

- **Handoff gate:** a "two readings" verdict sends a handoff back to the user only for direction or money; other cases pass and the decision is written under the handoff for the workspace to see (#1599).

## Improvements

- **Kickoff memory matches the task.** A workspace kickoff searches with the task line and the handoff's title, user quote and goal instead of the boilerplate prompt, and lines that mostly repeat the boilerplate no longer take a slot (#1600).
- **Built-in capabilities before new mechanisms.** When the user asks for a design or mechanism change, the lead first sees the matching built-in capabilities from `bothouse about`, similar past tasks and skills (#1598); the check-first hook blocks a proposal to build something new when a built-in capability does the same job and the reply never names it (#1600).
- **Hooks:** 11 rules that lived only in a hand-written global hook copy are merged into the shipped hooks (timeouts for long foreground commands, `pipefail` for piped tests, merge-gate check, no test posts in team chat channels, small-fix pass for the fix-claim check, subagent time limits and more) (#1596).
- **Discord:** new option `dm_deny_from` (comma-separated user IDs) drops DMs from those users, so two bridges sharing one bot token can answer one user's DMs from one machine only (#1601).

## 重点

- **子 agent 跑得久时插话有回应了。** 主会话在等前台子 agent 时你发消息，桥会把这个子 agent 转到后台（Claude Code 的 `background_tasks`），角色马上读到你的话并回答；子 agent 接着跑，跑完照常通知。后端做不到时，回一句这一轮在等哪个子 agent、等了几分钟，不再只有一个「已插入」（#1595）。
- **Claude CLI 成员能换模型。** 团队接口可以建 `cli: "claude"` 成员，两个成员 PATCH 入口都接受 Claude 模型 ID；下一轮发出前通过 ACP `session/set_model` 生效，`model: null` 恢复默认，切换失败就停下这一轮并报错（#1593，感谢 @jsk11231）。
- **夜间修复合集。** 角色 wiki 拿到调度器剩下的时间，夜间导出等 ingest 锁到预算就放手；setup 把内置 DSH 的数据放在自己的目录；DSH 默认用原生 DeepSeek，复用已选模型和 key；选了网关必须有自己的凭据；插件确认装上才报成功；发出去的消息留给下一轮上下文；QQ 保存失败不再显示「已连接」；`dsh web` 接管更严（#1594，感谢 @Zssan12）。

## 缺陷修复

- **交接闸：** 判成「两种理解」时，只有方向和花钱的事才退回问用户；其他情况放行，并把主角色的决定写在交接下面给工作区看（#1599）。

## 改进

- **开工推送按活本身匹配。** 工作区开工时用任务名和交接的标题、用户原话、总目标去搜，不再用模板开工词；和模板大半重复的条目不再占位置（#1600）。
- **提新机制前先看现成的。** 用户要改设计或机制时，主角色先看到 `bothouse about` 里对得上的内置能力、类似的旧活和 skill（#1598）；回复要新做的东西而内置能力已能做、又没提到它时，check-first 钩子会拦下（#1600）。
- **钩子：** 早先只写在全局手写守卫里的 11 条规则并进随包发的钩子（前台长命令限时、测试接管道加 `pipefail`、合并前问 merge-gate、团队聊天频道不发测试、小改免列入口表、子 agent 时限等）（#1596）。
- **Discord：** 新选项 `dm_deny_from`（逗号分隔的用户 ID），丢掉这些人发来的私聊；两个桥共用一个机器人令牌时，某人的私聊只由一台机器回（#1601）。
