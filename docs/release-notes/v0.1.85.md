## Highlights

- **Role cards, the Dashboard and web chat show the model the conversation is really using.** After a model switch a role could keep showing its configured default, and the Dashboard and the Roles page could disagree. Both now show the model from the role's latest conversation or model change and fall back to the default. Web chat keeps the conversation you selected across reloads, saves the model each turn reports so the label stays after a restart, and keeps a queued switch so it applies on the next turn even after a restart. Thanks @Hiennoob123 (#1982).
- **First run on a new install has fewer snags.** A new role gets an empty `diary.md`, so its first reply no longer carries a red "Bash · failed" card. When the DSH plugin is set up without a key, the bridge watches for a saved key and retries setup by itself; @ an offline DSH member now posts a card that says what to do (fill in the key and retry, or restart the bridge and retry). On a Chinese-language Mac the reply language is read from macOS, and `LANG=C` / POSIX is no longer taken as English (#2002).

## Fixes

- **DSH no longer shows "stopped" while DSH Desktop Channels is running.** The status check now finds the running Desktop host from its local owner record, checks its process and loopback address, and signs in to it, so a stale saved address no longer hides it. Thanks @Hiennoob123 (#1993, fixes #1992).
- **"Open in desktop app" comes back for desktop-only DSH installs.** The modules check counts DSH as enabled when either the desktop or the web profile has Channels turned on, so a missing or broken web profile no longer hides the button. Thanks @Hiennoob123 (#1984, fixes #1983).
- **DSH desktop: busy messages can join the running turn on more Windows layouts.** When the desktop launcher points into the app archive, the bridge now extracts the ACP module into the DSH profile, patches it there and refreshes the copy when DSH is upgraded. Checked with tests on that layout; not yet run on a real Windows desktop (#2001, refs #882).
- **The idle-workspace sweep actually frees workspaces.** A job paused for more than a day no longer holds its workspace, a paused job without a workspace only holds the one it last ran in, and no idle workspaces are kept back. The paused job itself is untouched and gets a fresh workspace when it resumes (#1996).

## Improvements

- **Team rules come from one place.** Every turn now carries this machine's house rules (`rules/house.md` under the data directory) after the team rules, and resends them when the file changes; the review and test rules in team mode are unified. At startup the bridge removes leftover hook entries for retired guards from the roles' settings (#1997).

## 重点

- **角色卡、仪表盘和网页聊天显示的是对话真正在用的模型。** 换过模型后，角色可能还显示配置里的默认模型，仪表盘和角色页也可能对不上。现在两处都显示这个角色最近一次对话或换模型时的模型，没有才用默认。网页聊天刷新后仍停在你选的那段对话；每轮回报的模型会存下来，重启后标签还在；排队的换模型也存下来，重启后照样在下一轮生效。感谢 @Hiennoob123（#1982）。
- **新装第一次跑少了几处卡顿。** 新角色会带一个空的 `diary.md`，第一条回复不再挂红色的「Bash · failed」卡片。DSH 插件没填密钥就设置时，桥会盯着密钥，存好后自己重试设置；@ 一个离线的 DSH 成员会发一张卡片，写明怎么办（填密钥后重试，或重启桥后重试）。中文 Mac 上回复语言从 macOS 读取，`LANG=C` / POSIX 不再当成英文（#2002）。

## 缺陷修复

- **DSH 桌面版 Channels 开着时，不再显示「已停止」。** 状态检查现在从本机的属主记录找到正在跑的桌面版，核对进程和本机地址后带凭据访问，存着的旧地址不再把它挡住。感谢 @Hiennoob123（#1993，修复 #1992）。
- **只装了桌面版 DSH 时，「在桌面应用中打开」回来了。** 模块检查里桌面版或网页版任一个开了 Channels 就算 DSH 已启用，网页版配置缺失或坏掉也不再把按钮藏起来。感谢 @Hiennoob123（#1984，修复 #1983）。
- **DSH 桌面版：更多 Windows 安装方式下，忙时发的消息能并进正在跑的那一轮。** 桌面启动器指向应用压缩包里时，桥现在把 ACP 模块解到 DSH 配置目录里打补丁，DSH 升级后自动重做。这种安装方式用测试验过，还没在真的 Windows 桌面上跑过（#2001，关联 #882）。
- **空闲工作区清扫真能腾出工作区了。** 暂停超过一天的活不再占着工作区；没绑工作区的暂停活只占它最后待的那一个；不再留空闲工作区。暂停的活本身不动，恢复时另取工作区（#1996）。

## 改进

- **团队规矩收成一处。** 每轮在团队规矩后附上本机守则（数据目录下的 `rules/house.md`），文件一改就重发；团队模式里审查和测试的规矩统一了。启动时桥把已退役守卫留在各角色设置里的挂载清掉（#1997）。
