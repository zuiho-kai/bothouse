## Highlights

- **Delete an idle workspace from the DSH channel list.** On the DSH web channel page, each workspace row now has a × (shown on hover; always shown on a phone). An idle workspace: click ×, confirm once, and it leaves the list for good. A workspace with a job in work shows the × dimmed and says it can be deleted once the work is done. A workspace where a paused job waits to continue is refused with the reason. Deleting cannot be undone. On Discord and Feishu a workspace channel is still deleted on the platform itself. Asked for in #1904 (#1963, #1967).
- **A job can hand back its results in batches.** A workspace can hand in part of a job with `ws-up --report <draft> --batch`. Accepting a batch keeps the job and its workspace open; accepting the final report closes the job. A final report that is sent back for rework is claimed again in one step, and the same report text can be handed in again after a rejection (#1946, thanks @Zssan12).

## Fixes

- **Pictures and files from an old workspace job no longer land in another job's chat.** When a workspace moved on to a new job, a picture or file sent without a target by the earlier job (by another role still working there, or by a background command the same role had left running) was posted to the new job's chat channel. Each role process now knows which job it was started for. An attachment goes to the chat channel only while that job is still in work; otherwise it stays in the workspace channel, and the command prints the reason and how to send it to the channel you mean. Text-only sends and sends with an explicit target are unchanged. Reported in #1959 (#1958, #1962).
- **The first turn of a newly handed job no longer waits two minutes.** A role process that was still alive in the workspace because of a background command is restarted for the new job. The restart used to wait the full two minutes for the process to leave by itself. It now stops that process at once; in our run the first turn went from 2m10s to 8.5s (#1965).
- **DSH on Windows: a message for a busy role can join the running turn again.** A message that @-mentions a busy DSH role joins its current turn through a small patch the bridge keeps in DSH. On Windows, npm installs DSH behind a `dsh.cmd` launcher; the bridge could not find the DSH package behind it, so the patch was never put back after a DSH upgrade and such messages waited in the queue until the long task ended. The bridge now resolves the launcher and restores the patch when a session starts. Checked on macOS and by a regression test; a retest on a real Windows machine is welcome in #882 (#1964).
- **Windows: the background wiki worker no longer opens terminal windows.** When a role session closed, the background wiki worker could pop up visible console windows. It now starts with a hidden console that its helper programs inherit. An upgrade also replaces the installed copy of the worker script, so existing installs get the fix; a copy you edited yourself is left alone (#1957, thanks @Hiennoob123; #1960).
- **A workspace is not woken while its background command is running, and a job in work keeps its workspace.** An unfinished workspace could be nudged as "no progress" while its background command was still running, and a second claim could replace the workspace of a job in work while the first handoff stayed alive. A claim to another workspace is now refused until the job leaves its current one (#1938, thanks @Zssan12).
- **`bgrun` reports a start only when the command really started.** A command that was missing or failed at once was reported as started, and closing the agent's tool process could take the background supervisor down with it. The supervisor now runs in its own session and confirms the launch; a failed start returns an error with the log. The bridge and `bgrun` also use the same run folder (#1940, thanks @Zssan12).
- **Background progress is judged by recent output.** A tracked background command with no time limit could stay silent forever and keep the "no progress" nudge off. It now counts as progress only while its log has been updated within the watch interval (ten minutes by default). A command that keeps printing is no longer cut by the renewal limit (#1955, thanks @Zssan12).
- **Discord: a role in a workspace channel can only mention registered bots.** A role working in a workspace could @ a person directly to ask for a decision. Workspace messages now allow mentions of registered bot accounts only, and questions that need a decision go through `ws-up --ask`. Chat channels mention as before (#1956, thanks @Zssan12).
- **Stopping the bridge waits for timer callbacks in progress.** A timer callback that was still writing when the scheduler stopped could write after its storage was released. Stop now cancels pending timers and waits for the callbacks that are running (#1945, thanks @Zssan12).
- **Role memory gets its share of the pushed rows.** When the shared wiki had five or more matching rows, they used the whole budget of a turn and the role's own wiki got none. Rows are now taken in turn from both; the total stays at five (#1948, thanks @Zssan12).

## Improvements

- **A pushed memory row must relate to the turn's own words.** A row that shares no word with what the turn is about is no longer pushed. An optional rerank service can score the rows instead (`GATE_RERANK=<url>`); with no service or no answer in two seconds the word rule applies (#1966).
- **The nightly day pack shows cost per job.** Its cost part now lists cost per board task, split between the main agent and sub-agents, the calls whose context is over 300k, and the rewrites that follow a compaction (#1968).

## 重点

- **在 DSH 频道列表里删掉空闲的工作区。** DSH 网页版的频道页，每个工作区那一行多了一个 ×（鼠标移上去出现，手机上一直显示）。空闲的工作区：点 ×，确认一次，它就从列表里消失。还有活在做的工作区：× 是灰的，并告诉你做完才能删。里面有暂停的活等着接着做的工作区：会拒绝并说明原因。删除不能恢复。Discord 和飞书上的工作区频道仍在平台里自己删。来自 #1904 的需求（#1963、#1967）。
- **一件活可以分批交回。** 工作区可以用 `ws-up --report <草稿> --batch` 先交一部分。验收一批不会关掉这件活，工作区也留着；验收最终那份才关。最终那份被退回返工时，一步就重新认领；被退回后可以用同一份文字再交（#1946，感谢 @Zssan12）。

## 缺陷修复

- **旧活的图片和文件不再发进别的活的聊天频道。** 工作区换了新活之后，旧活那边不带目标发出的图片或文件（还在里面干活的另一个角色发的，或者同一个角色留下的后台命令发的）会进到新活的聊天频道。现在每个角色进程都知道自己是为哪件活启动的。这件活还在做，附件才回它的聊天频道；否则留在工作区频道，命令会直接说明原因，以及怎么发到你想发的频道。纯文字和指定了目标的发送不变。#1959 报告的问题（#1958、#1962）。
- **新派的活第一轮不再干等两分钟。** 工作区里因为后台命令还活着的角色进程，会为新活重启一次。以前这次重启要等满两分钟让它自己退出。现在直接停掉它；我们实测第一轮从 2 分 10 秒降到 8.5 秒（#1965）。
- **Windows 上的 DSH：发给忙碌角色的消息又能插进当前这一轮。** @ 一个正忙的 DSH 角色时，消息靠桥放在 DSH 里的一个小补丁插进它当前这一轮。Windows 上 npm 把 DSH 装在 `dsh.cmd` 启动器后面，桥找不到后面的 DSH 包，DSH 升级后补丁就一直没补回去，这类消息只能排队到长任务结束。现在桥能认出这个启动器，并在会话启动时把补丁补回去。已在 macOS 上和回归测试里验过；欢迎在 #882 里用 Windows 真机复测（#1964）。
- **Windows：后台 wiki 进程不再弹终端窗口。** 角色会话关闭时，后台 wiki 进程可能弹出可见的控制台窗口。现在它带一个隐藏的控制台启动，它起的辅助程序也沿用这个控制台。升级时还会替换已安装的那份脚本，所以老用户也能拿到修复；你自己改过的那份不动（#1957，感谢 @Hiennoob123；#1960）。
- **后台命令还在跑的工作区不会被叫醒，在做的活不会被换走工作区。** 以前没做完的工作区在后台命令还在跑时会被当成「没进展」催一次；第二次认领还可能把在做的活换到另一个工作区，而原来的交接还活着。现在这件活离开当前工作区之前，认领别的工作区会被拒绝（#1938，感谢 @Zssan12）。
- **`bgrun` 只在命令真的起来了才报已启动。** 以前命令不存在或立刻失败也报成已启动；关掉角色的工具进程还可能连后台看护一起带走。现在看护在自己的会话里跑，并确认命令已启动；启动失败会报错并给出日志。桥和 `bgrun` 也用同一个运行目录（#1940，感谢 @Zssan12）。
- **后台有没有进展看最近的输出。** 以前没设时限的后台命令可以一直不出声，「没进展」的提醒也一直被压着。现在只有日志在看护间隔内（默认十分钟）有更新才算有进展。一直在输出的命令不再被续期上限打断（#1955，感谢 @Zssan12）。
- **Discord：工作区频道里的角色只能 @ 已登记的机器人。** 以前工作区里的角色可能直接 @ 真人要决定。现在工作区消息只允许 @ 已登记的机器人账号，要拍板的问题走 `ws-up --ask`。聊天频道照常 @（#1956，感谢 @Zssan12）。
- **停桥时等正在跑的定时回调写完。** 以前调度器停下时还在写的定时回调，可能在存储释放之后才写。现在停止时取消还没到点的定时，并等正在跑的回调结束（#1945，感谢 @Zssan12）。
- **角色自己的记忆也分得到推送的行数。** 以前共享 wiki 命中五行以上时，会占满一轮的额度，角色自己的 wiki 一行也没有。现在两边轮流取，总数仍是五行（#1948，感谢 @Zssan12）。

## 改进

- **推送的记忆要和这一轮说的话有关。** 和这一轮在说的事没有一个共同词的行不再推送。也可以接一个重排服务来打分（`GATE_RERANK=<url>`）；没配或两秒内没回答就按共同词的规则（#1966）。
- **每晚的日报包按活显示花费。** 花费部分现在列出每件任务板任务的花费（主角色和子 agent 分开）、上下文超过 30 万的调用，以及压缩之后的重写（#1968）。
