## Highlights

- **Idle workspaces are deleted for good, each one archived first.** The bridge now sweeps once an hour and deletes the idle workspaces it no longer needs, keeping the lowest two. A workspace is idle when nothing is in work or paused there and no turn is running; it also has to have been quiet for two hours. Before a channel goes, the bridge writes one compressed archive (`.tar.gz`) under the data directory, holding that workspace's channel messages, the bridge's records for it, the roles' sessions, the agent transcripts and the handoff files its messages name. If the archive cannot be written, the workspace is not deleted. Discord: the workspace channel is deleted on Discord, so the sweep reads its whole history first. On the DSH web page the room simply leaves the channel list, and the archive there has the records, sessions and handoffs (the room's messages stay with the gateway). The deletion always follows an accepted hand-back, never takes a workspace a chat channel owns, and a paused job's workspace is left alone. The hourly loop starts ten minutes after the bridge is up, so it no longer runs before the platforms have connected (#1988, #1989, #1990).
- **A waiting task post now waits on whoever handed the job out, not on you.** A board post that says it is waiting used to count as "waiting for the user" whenever its status mentioned the user, so it could @ you directly even though the role that dispatched the job had never forwarded that question. Now only a question the dispatcher actually forwarded (`ws-forward --ask-user`) waits on you; everything else waits on the dispatcher, and the post names it on its first line. A dispatcher that is a bot is written by name without a mention; a dispatcher that is a real person is mentioned once, as before (#1987).

## Fixes

- **A project in quota cooldown no longer spawns a new workspace on every retry.** While the project was cooling down, a task waiting on something external was retried every ten minutes; every claim failed with the cooling error and the dispatcher made another workspace each round (工作区12–37 in one day). Now a cooling error ends the attempt at once — no next workspace, no new one — an idle workspace whose claim failed is not replaced, and at most one new workspace is made per board item per 30 minutes. The waiting retry is skipped while the project is cooling (#1986).
- **A one-off scheduled run keeps its agent while background work is still running.** A pre-market cron run started a script in the background and ended its first turn; the cron path then cleaned up the session and killed the follow-up turn two minutes later, while it was still writing. A run now leaves the agent alone while it still has background work, and the existing idle close ends it when that work finishes. One-off timer sessions get the same treatment (#1985).

## 重点

- **空闲的工作区会真的删掉，删之前先存一份压缩归档。** 桥现在每小时扫一遍，把用不上的空闲工作区删掉，编号最小的两个留着。空闲是指里面没有在做的活、没有暂停等着接着做的活，也没有一轮正在跑；还要安静满两小时。删之前先在数据目录下写一个压缩包（`.tar.gz`），里面是这个工作区的频道消息、桥给它的记录、各角色的会话、角色进程的记录，还有它消息里点到的交接文件。压缩包写不出来就不删。Discord：工作区就是频道，删除前先把整段历史读下来。DSH 网页版上房间只是从频道列表里消失，归档里是记录、会话和交接文件（房间消息在网关那边）。只删已经验收交回的空闲工作区，聊天频道正在用的不动，有暂停的活等着接着做的工作区也不动。每小时这一轮在桥起来十分钟后才开始，不会赶在平台连上之前跑（#1988、#1989、#1990）。
- **等拍板的帖子现在等的是派活的人，不是你。** 任务板上的帖子只要状态里提到用户，以前就算「等你拍板」，可能直接 @ 你，而派这件活的主角色其实没把问题转给你。现在只有派活的人真的转过来的问题（`ws-forward --ask-user`）才算等你；其余的等派活的人，帖子第一行写明是谁。派活的人是机器人就只写名字、不 @；是真人才 @ 一次，和以前一样（#1987）。

## 缺陷修复

- **项目额度冷却时重试不再每一轮建一个新工作区。** 项目在冷却时，一件等外部条件的活每十分钟重试一次，每次认领都因冷却失败，派活的脚本每一轮又建一个新工作区（一天里出现了工作区12–37）。现在冷却错误直接结束这一次尝试，不换工作区、也不新建；认领失败的空闲工作区不补建；同一条任务板条目 30 分钟内最多新建一个工作区。项目冷却期间也不再做这个等待重试（#1986）。
- **一次性的定时任务有后台活在跑时不再把角色杀掉。** 盘前的一次性定时任务把材料脚本放到后台、先结束第一轮；定时这条路随后清理会话，两分钟后把醒来续跑、正在写判断的那一轮杀了。现在角色还有后台活时这里不关它，交给已有的「回合结束空闲关闭」，后台活做完那一轮结束时再关。一次性的定时会话同样处理（#1985）。
