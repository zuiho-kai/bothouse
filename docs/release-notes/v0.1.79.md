## Highlights

- **A quieter, tidier task forum.** A message in a task post wakes the lead only when it @-mentions the bot or replies to one of its messages, so people talking to each other no longer start turns (#1714). A waiting post mentions the user only when it has a real question, not when the bridge has written its own step line (#1712). A reply typed while the session is busy joins the running turn when the agent accepts steering, with an "↪ inserted" receipt in the post (#1715). The posts themselves keep the current state, what is needed and the conclusion (#1699), archive as soon as the task is done and reopen if it resumes (#1698), and name the speaker of each quote line (#1871, #1872, #1873).

## Fixes

- **A finished report keeps its four parts in the chat channel**: with the task forum on, the report keeps its headline and adds the post link instead of replacing the headline with the link (#1710).
- **No done without a hand-back**: a workspace can no longer mark a task done or accepted without handing the result back; the later reminder now points to the hand-back command (#1695).
- **Handoff repair check**: a handoff that only cites a ticket number is no longer treated as a bug fix, so it is not asked for a root cause (#1867).
- **QQ liveness**: a OneBot connection that stays silent past two heartbeats is treated as dead and reconnected; a server that never sends heartbeats is untouched (#1886).
- **Antigravity turn evidence**: input from a hook during a turn no longer invalidates that turn's evidence (#1713).

## Improvements

- **Per-turn spend caps**: cron, timer and workspace turns read the CLI's own usage every 15 seconds and stop mid-turn above the cap, with a notice naming the task, the spend and the cap; `[turn_spend_cap]` overrides the defaults (cron $1, timer $5, workspace $20). Backends that write no usage log are not metered (#1701).
- **Pinned board table**: each row links to the item's own forum post (#1707).
- **Workspace read marks**: a handoff session starts its backfill at the start notice (#1705), clearing a session marks the channel seen (#1705), and the newest-post read skips progress-only cards (#1705).

## 重点

- **任务帖子更安静、更干净。** 帖子里的消息只有 @ 机器人或回复机器人的消息才会叫醒主角色，人和人说话不再各开一轮（#1714）。等拍板的帖子只在真有问题时 @ 用户，桥自己写的「在做：……」不再被当成问题（#1712）。会话忙时帖里的回复能插进正在跑的一轮（agent 支持中途输入时），帖里回「↪ 已插入」（#1715）。帖子只留现状、要你做的和结论（#1699），任务完成当场归档、返工再打开（#1698），引用行标出是谁说的（#1871、#1872、#1873）。

## 缺陷修复

- **交回的结果在聊天频道保留四段**：开着任务帖子区时，交回不再只剩一个帖子链接，而是四段头条后面附上链接（#1710）。
- **没交回不能标完成**：工作区没把结果交回时不能再把任务标成完成或验收；later 到点的提示改成让工作区用交回命令（#1695）。
- **交接的修 bug 判断**：交接里只是引用编号时，不再被判成修 bug，也不再要求根因（#1867）。
- **QQ 连接存活**：OneBot 超过两个心跳没有消息就判连接已死并重连；本来就不发心跳的服务端不受影响（#1886）。
- **Antigravity 的轮次证据**：一轮进行中 hook 送进来的输入不再把这轮证据判失效（#1713）。

## 改进

- **每轮花费上限**：cron、定时和工作区的轮每 15 秒读一次 CLI 自己的用量，超过上限就中途停掉这一轮，并在发起频道通知是哪件活、花了多少、上限多少；`[turn_spend_cap]` 可改默认值（cron 1 美元、定时 5 美元、工作区 20 美元）。没有用量日志的后端不计费（#1701）。
- **任务板表格**：钉住的表格每一行链到这件活自己的帖子（#1707）。
- **工作区的已读记号**：接手会话从「工作区接手」那条开始回读（#1705），清会话时把频道标成已读（#1705），最新一条是只有卡的进度卡时也能读对（#1705）。
