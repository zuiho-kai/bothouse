## Highlights

- **A quieter, tidier task forum.** A message in a task post wakes the lead only when it @-mentions the bot or replies to one of its messages, so people talking to each other no longer start turns (#1882). A waiting post mentions the user only when it has a real question, not when the bridge has written its own step line (#1883). A reply typed while the session is busy joins the running turn when the agent accepts steering, with an "↪ inserted" receipt in the post (#1885). The posts themselves keep the current state, what is needed and the conclusion (#1869), archive as soon as the task is done and reopen if it resumes (#1868), and name the speaker of each quote line (#1871, #1872, #1873).

## Fixes

- **A finished report keeps its four parts in the chat channel**: with the task forum on, the report keeps its headline and adds the post link instead of replacing the headline with the link (#1880).
- **No done without a hand-back**: a workspace can no longer mark a task done or accepted without handing the result back; the later reminder now points to the hand-back command (#1865, #1888).
- **Handoff repair check**: a handoff that only cites a ticket number is no longer treated as a bug fix, so it is not asked for a root cause (#1867).
- **QQ liveness**: a OneBot connection that stays silent past two heartbeats is treated as dead and reconnected; a server that never sends heartbeats is untouched (#1887).
- **Quota cooldown no longer flaps**: when the usage panel shows a window at 100% but the provider keeps answering, the real answer wins, so the lead and the work no longer move to another teammate on every turn; a provider quota error still starts the cooldown. Reset times written as "Nov 20 at 2pm" are now parsed (#1891).
- **Codex on Windows opens no console window**: started from the tray, the bridge has no console, so `codex.exe` used to get a console window of its own, and closing that window ended the running turn with `0xC000013A`. The app-server child now starts without a window (#1894, original change by @Ainz-X in #478).
- **Antigravity turn evidence**: input from a hook during a turn no longer invalidates that turn's evidence (#1714).

## Improvements

- **Per-turn spend caps**: cron, timer and workspace turns read the CLI's own usage every 15 seconds and stop mid-turn above the cap, with a notice naming the task, the spend and the cap; `[turn_spend_cap]` overrides the defaults (cron $1, timer $5, workspace $20). Backends that write no usage log are not metered (#1870).
- **Pinned board table**: each row links to the item's own forum post (#1877).
- **Workspace read marks**: a handoff session starts its backfill at the start notice (#1874), clearing a session marks the channel seen (#1878), and the newest-post read skips progress-only cards (#1879).

## 重点

- **任务帖子更安静、更干净。** 帖子里的消息只有 @ 机器人或回复机器人的消息才会叫醒主角色，人和人说话不再各开一轮（#1882）。等拍板的帖子只在真有问题时 @ 用户，桥自己写的「在做：……」不再被当成问题（#1883）。会话忙时帖里的回复能插进正在跑的一轮（agent 支持中途输入时），帖里回「↪ 已插入」（#1885）。帖子只留现状、要你做的和结论（#1869），任务完成当场归档、返工再打开（#1868），引用行标出是谁说的（#1871、#1872、#1873）。

## 缺陷修复

- **交回的结果在聊天频道保留四段**：开着任务帖子区时，交回不再只剩一个帖子链接，而是四段头条后面附上链接（#1880）。
- **没交回不能标完成**：工作区没把结果交回时不能再把任务标成完成或验收；later 到点的提示改成让工作区用交回命令（#1865、#1888）。
- **交接的修 bug 判断**：交接里只是引用编号时，不再被判成修 bug，也不再要求根因（#1867）。
- **QQ 连接存活**：OneBot 超过两个心跳没有消息就判连接已死并重连；本来就不发心跳的服务端不受影响（#1887）。
- **额度冷却不再来回跳**：用量面板显示某个窗口 100%、但模型还在正常回答时，以真实回答为准，主角色和手上的活不再每轮都被转给别的队友；模型真报额度用尽时照旧冷却。「Nov 20 at 2pm」这种写法的重置时间现在能读出来（#1891）。
- **Windows 上 Codex 不再弹控制台窗口**：桥从托盘启动时自己没有控制台，`codex.exe` 会另开一个控制台窗口，关掉它就让正在跑的一轮以 `0xC000013A` 失败。现在 app-server 子进程不带窗口启动（#1894，原始改动来自 @Ainz-X 的 #478）。
- **Antigravity 的轮次证据**：一轮进行中 hook 送进来的输入不再把这轮证据判失效（#1714）。

## 改进

- **每轮花费上限**：cron、定时和工作区的轮每 15 秒读一次 CLI 自己的用量，超过上限就中途停掉这一轮，并在发起频道通知是哪件活、花了多少、上限多少；`[turn_spend_cap]` 可改默认值（cron 1 美元、定时 5 美元、工作区 20 美元）。没有用量日志的后端不计费（#1870）。
- **任务板表格**：钉住的表格每一行链到这件活自己的帖子（#1877）。
- **工作区的已读记号**：接手会话从「工作区接手」那条开始回读（#1874），清会话时把频道标成已读（#1878），最新一条是只有卡的进度卡时也能读对（#1879）。
