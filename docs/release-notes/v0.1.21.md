### Fixes

- **Switching the lead role takes effect.** After you switch the lead (from the member bar, by telling the router, or with `lead me`), messages with no @ go to the new lead, also for teams set up by the wizard. The router also accepts phrasings such as "你现在是主bot", and only when the sentence ends after the role word (#331, #337).
- **A permission request is approved only once.** When one approver has already allowed or denied a request, later approvals for the same request are dropped instead of being sent again (#336).
- **"停" with no @ stops every bot in the channel.** A bare stop word stops the work of all bots in that channel (Discord); `@bot 停` still stops only that bot. A thread and its parent channel are stopped separately (#335).
- **Upgrade turns on full-auto for roles that never had a permission mode.** On the first start after the upgrade, roles with no permission mode set get the same full-auto default that the wizard gives new roles. This runs once, keeps your comments, skips configs it cannot edit safely, and restores the file if the write fails (#334, #340).

### Changes

- **Team board is on by default for the lead.** A config without `team_board` now shows the board; `team_board = false` still turns it off (#332).
- **Wizard teams with two or more roles get team status and the board with no config edits.** The default lead is the wizard's fallback role (#339).
- **Clear hint when a teammate is not bound in this channel.** Delegating or relaying to a teammate not bound here now says which `/bind <project>` the user should send in this channel. An empty workspace list tells you how to create the first workspace (#338).
- **Lead rules: open a task card first, create a workspace for big work, ask the user to /bind.** (#333)
- **Wizard: routing checkbox on by default.** Step 4 of the web wizard has a "routing: one lead bot decides who replies (recommended)" checkbox, checked by default; the result page shows the routing status (#341).

### 缺陷修复

- **切主角色会生效。** 在成员栏、对分流说、或用 `lead me` 切主后，没 @ 的消息由新的主角色回答，向导建的团队也一样。分流也认「你现在是主bot」这类说法，但角色名后面只能跟语气词和标点（#331、#337）。
- **代批只批一次。** 一个审批人已经同意或拒绝后，别的审批人对同一请求的代批会被丢掉，不再重复发出（#336）。
- **没 @ 的「停」会停下频道里所有 bot。** 只说停字时，这个频道里所有 bot 都停下手上的活（Discord）；`@bot 停` 仍只停那一个。子区和母频道分开停（#335）。
- **升级时给没设权限模式的角色补上免审批。** 升级后第一次启动，没设过权限模式的老角色改成和向导新角色一样的免审批默认值。只跑一次，保留注释，不能安全改写的配置跳过，写坏了会还原（#334、#340）。

### 改动

- **任务板默认对主角色打开。** 配置里没写 `team_board` 时显示任务板；写了 `team_board = false` 仍然关闭（#332）。
- **向导建的两个及以上角色的团队，不改配置就有团队状态和任务板。** 默认主角色是向导里的兜底角色（#339）。
- **队友没在本频道绑定时给出明确提示。** 派活或转发给本频道没绑定的队友时，提示用户在本频道发 `/bind <项目>`；工作区列表为空时提示怎样建第一个工作区（#338）。
- **主角色规矩：先开任务卡，大活建工作区，请用户 /bind。**（#333）
- **向导：分流勾选框默认勾上。** 网页向导第 4 步新增「分流：一个主 bot 决定谁回话（推荐）」勾选框，默认勾选；结果页显示分流状态（#341）。
