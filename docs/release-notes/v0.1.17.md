### New

- **Channel approval cards for DSH members.** Members talking in a DSH channel run in background sessions, so their permission prompts now show up as cards in the channel where you @-mentioned them. Click **Allow** / **Deny** (or reply in text). Members set to **Full access** don't ask (#290).
- **Local CLI members follow DSH permission presets.** When a local CLI member wants to run a tool, it now follows the same presets as native DSH members, selectable in member settings: **Full access** runs it right away, the default **Workspace Write** posts an approval card in the channel, and **Read Only** refuses tool calls that would change anything (#298).
- **Members receive attachments.** Images and files you send in a channel now reach native DSH members and local CLI members. If an attachment is too large, the text still goes through, the channel says the attachment wasn't delivered, and the room keeps working (#291).
- **"Come back later" for every member.** cc-connect members, native DSH members and local CLI members can each schedule a one-shot follow-up. When it's due, the same member wakes up in the same room and carries on. It survives restarts, and a member can't schedule one on behalf of another member or another room (#291).
- **`/new` in DSH channels.** Like on Discord, `/new` starts a fresh session for the member(s) you @-mention in that message (the main member if none); other members keep theirs (#290).

### Fixes

- **Local CLI members pick up where they left off.** After a restart or a crash, a local CLI member continues its previous conversation. If the CLI can't resume it, the channel now says plainly that this turn starts a new session, instead of silently forgetting (#286).
- **Member presets in the config file are kept.** A member configured as **Full access** in the config file no longer raises approval cards (#296).
- **Archived member sessions no longer break the channel.** Member background sessions stay out of the DSH conversation list; if one was archived or deleted anyway, the next @ starts a new session instead of failing (#290).

### 新功能

- **DSH 成员的审批卡发到频道里。** 频道里的成员在后台会话里干活，需要授权时，审批卡会出现在你 @ 它的那个频道，点「允许」/「拒绝」或直接回文字都行。设成「完全权限」的成员不问（#290）。
- **本机 CLI 成员按 DSH 权限档位审批。** 本机 CLI 成员要调工具时，和 DSH 原生成员用同一套档位，可在成员设置里选：「完全权限」直接放行；默认的「工作区内修改」在频道里发审批卡；「仅可查看」把要动手的工具调用一律拒绝（#298）。
- **成员能收附件了。** 频道里发的图片和文件，DSH 原生成员和本机 CLI 成员现在都能收到。附件超限时文字照常送达，频道会提示附件没送到，房间之后照常对话（#291）。
- **三类成员都能「过会儿回来」。** cc-connect 成员、DSH 原生成员、本机 CLI 成员都能登记一次性的「过会儿回来」，到点由同一个成员在原房间被叫醒接着做；重启后照常触发，成员不能替别的成员或别的房间登记（#291）。
- **DSH 频道支持 `/new`。** 和 Discord 一样，`/new` 只重置这条消息里 @ 到的成员（没 @ 就是主成员），其他成员的会话不变（#290）。

### 缺陷修复

- **本机 CLI 成员重启后接着聊。** 重启或崩溃后，本机 CLI 成员续上原来的会话；该 CLI 续不上时，频道里会明说「这轮起是新会话」，不再无声失忆（#286）。
- **配置文件里的成员档位不再丢。** 配置文件里设成「完全权限」的成员不会再弹审批卡（#296）。
- **归档了成员会话也不会卡住频道。** 成员的后台会话不再出现在 DSH 会话列表里；万一被归档或删除，下次 @ 会开新会话，不再报错（#290）。
