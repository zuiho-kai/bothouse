## Highlights

- **Cron jobs can run on events.** `bothouse cron add --event <name> [--match k=v]` runs a job when something happens instead of on a schedule, in the same store and with the same list/info/edit/del. Sources are bridge events, `POST /events` and `bothouse cron fire`. A workspace hand-back now wakes the role that dispatched it, not only the lead (#2140, #2141).
- **Private channels keep their task posts private.** A channel hidden from everyone gets its task posts as threads inside itself instead of in the shared category forum, so members of one private channel no longer see another's tasks (#2137).
- **Context blocks are sent once per session.** Everything the bridge puts in front of a message goes through one outlet and is sent once per agent session by default (again after a new session, a switch or compaction); per turn only memory-forum titles are added, as short titles with an id (#2114, #2113, #2128, #2129).
- **Approved work stays approved.** Board tasks have a sample and a full stage; the full stage needs the user's recorded approval of the sample, and the approved piece is shown at the start of every new session. Before a deliverable goes out it is compared side by side with the original or the approved sample (#2116, #2117).
- **Hand-off notes remember corrections.** Hand-off digests get a "what the user corrected" section, and a correction made today reaches the same role's other channels (#2115).
- **A restart no longer loses background work.** Background work still running is recorded; `safe-restart` waits for it, and after a restart the session is told what was stopped (#2111). Restart catch-up now covers a whole night's downtime, reads past 50 posts per channel and says the message came while the bridge was down (#2143).

## Fixes

- **Discord: one closed rate-limit bucket no longer freezes the bot.** A guild channel call that Discord blocks for a long time fails fast, and a task post that cannot be opened backs off per chat instead of retrying every pass; messages are routed without waiting for the task-post sync (#2133).
- **Discord private rooms with several bots:** a message addressed to another bot is not taken as a call to this one, and a channel with several bots is not treated as a one-to-one room (#2142).
- **Images:** the image type is read from the bytes, not the platform label, fixing DSH error -32602 on PNG screenshots labelled as JPEG (#2124).
- **Workspace reports:** held reports post their pictures and videos in the chat channel (#2103); a reference task's attachments wait for the check against the original (#2112), and at the unchecked timeout they are posted marked as unjudged, together with the item-by-item block (#2144, #2145, #2146); `ws-pass --verdict` carries the workspace's final text (#2139); duplicate videos of the same edition are dropped (#2131); a wake-up for a held report is always delivered, also across a restart (#2120).
- **Workspaces:** a pool workspace with a running turn is not handed out as free (#2109); hand-off checks are owned by one rule table (#2110).
- **Cron/timer:** a successful exec job with no output no longer posts "✅ (no output)" (#2105).
- **Memory forum:** forum and nightly-scoring changes that only lived on one machine are now in the product (#2106).
- **Copy checks:** external copy is held until the reference lines are in the draft; chat replies no longer go through it, and new checks only log until a replay shows few misfires (#2121, #2125, #2126).

## Improvements

- **Feishu:** a sub-agent progress table card, and `allow_bots` / `team_lead_bot` apply without a restart (#2127).

## 重点

- **定时任务可以按事件触发。** `bothouse cron add --event <名字> [--match k=v]` 让任务在某件事发生时跑，不按钟点；和定时任务同一份存储，list/info/edit/del 照用。事件来自桥自身、`POST /events` 和 `bothouse cron fire`。工作区交回现在会叫醒派活的那个角色，不只叫主角色（#2140、#2141）。
- **私密频道的任务帖不再外露。** 所有人都看不见的频道，任务帖开成频道里的子话题，不再进同分类共用的论坛，一个私密频道的成员看不到另一个的任务（#2137）。
- **贴在消息前的说明每个会话只发一遍。** 桥贴在消息前的各块统一从一个出口走，默认每个会话发一次（新会话、换会话、压缩后再发）；每轮只加记忆论坛的标题，只给短标题和编号（#2114、#2113、#2128、#2129）。
- **认可过的成品不走样。** 任务板的成品活分「样」和「全量」两段，没有用户对样的认可记录进不了全量；认可过的那份在每个新会话开头带上。成品发出前和原件或认可样并排对照（#2116、#2117）。
- **交接纪要记住纠正。** 交接纪要加「用户纠正过的」一栏，当天的纠正带到同角色的其他频道（#2115）。
- **重启不再弄丢后台的活。** 还在跑的后台活会被记下；`safe-restart` 等它交回再重启，重启后会话会被告知哪些被停了（#2111）。重启补回覆盖一整晚的停机，每个频道能读过 50 条，并说明这条是停机时发的（#2143）。

## 缺陷修复

- **Discord：一个被关掉的限流桶不再把机器人卡死。** Discord 长时间封住的服务器频道调用直接失败；开不出任务帖时按聊天各自退避，不再每轮重试；收到的消息不再等任务帖同步（#2133）。
- **Discord 多机器人私密房间：** 说给别的机器人的话不再当成叫自己；有多个机器人的频道不算一对一房间（#2142）。
- **图片：** 图片类型按字节判断，不信平台标签，修好 PNG 截图被标成 JPEG 时 DSH 报 -32602（#2124）。
- **工作区交回：** 待验收的交回把图片和视频发到聊天频道（#2103）；照参考做的活，附件等对照原件后再发（#2112），验收超时时标「未判」照发，并带逐条材料块（#2144、#2145、#2146）；`ws-pass --verdict` 放行时带上工作区交回的定稿（#2139）；同一版视频去重（#2131）；待验收的叫醒必定送到，重启过点也补（#2120）。
- **工作区：** 正在跑一轮的池工作区不再被当成空闲（#2109）；交接检查由一张规则表统一管（#2110）。
- **定时任务：** exec 成功且没有输出时不再发「✅ (no output)」（#2105）。
- **记忆论坛：** 只在一台机器上改过的论坛和夜间打分改动进了产品（#2106）。
- **文案检查：** 对外文案在稿里摆出对标原句前不放行；聊天回复不再过这道检查，新检查先只记日志，回放误拦少了再拦（#2121、#2125、#2126）。
