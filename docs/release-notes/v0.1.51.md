## Highlights

- **"Open DSH" has no start deadline any more.** While `dsh web` is still starting, the wizard keeps waiting and shows how long it has waited and DSH's last log line; only an exit counts as a failure. Clicking again, opening a second tab or restarting bothouse picks up the same starting DSH instead of starting another one. A first start on Windows was measured at 2 min 31 s, which used to fail at 60 s (#1075, #1082).
- **Platform event trigger.** The bridge publishes platform events to `events.jsonl` and to `[[hooks]]`, with filters by server, channel and user. Discord: members joining or leaving, reactions, channels and threads, voice, pins. Feishu and QQ have the same member events, and QQ also has emoji likes. Nothing is subscribed and no role is woken by default. When the members intent is off, you still get a reminder (#1073, #1074, #1076, #1077).
- **Who started this turn, signed by the bridge.** Tools in a turn can get a 5-minute token signed by the bridge that says which person started the turn. `bothouse guard` is a reference permission gate: it checks the token against an admin table, runs only fixed commands as the mapped account, writes an audit log, and only lets turns started by a person through (#1078, #1079, #1081).
- **bothouse pages are DSH plugin rows.** Channels, team desk, the bothouse panel and other computers each have their own on/off switch in DSH → Plugins → bothouse. New installs start with only Channels on. Upgrades keep the sidebar as it was (#1054).

## Fixes

- **Windows "Open DSH" after an update:** a `dsh web` the bridge no longer tracks is adopted when its token still signs in, or stopped first. The gate starts before DSH, so a slow DSH start does not leave members without it (#1075).
- **Lead switch by the user works in single-role and gate-only setups:** gate recognises "you are the lead" before its 503 and single-role paths (#1070).

## Improvements

- **CI:** `bothouse guard help` exits 0 like every other command. The upgrade test now edits a collab patch from after #1044, because older patches are replaced by design (#1082).

## 重点

- **「打开 DSH」不再有启动时限。** `dsh web` 还在启动时，向导一直等，显示已等多少秒和 DSH 日志最后一行；只有进程退出才算失败。再点一次、再开一个标签页、重启 bothouse，都会接上同一个正在启动的 DSH，不另起一个。Windows 首启实测要 2 分 31 秒，以前等 60 秒就判失败（#1075、#1082）。
- **平台事件触发器。** 桥把平台事件写进 `events.jsonl` 并触发 `[[hooks]]`，可以按服务器、频道、用户过滤。Discord 有成员进退群、表情、频道和子区、语音、置顶；飞书和 QQ 有同名的成员事件，QQ 还有表情点赞。默认不订阅，也不叫醒任何角色；没开成员权限时仍会提醒（#1073、#1074、#1076、#1077）。
- **桥签名的「这一轮是谁发起的」。** 一轮里的工具可以取一张桥签名的 5 分钟凭证，写明是哪个真人发起了这一轮。`bothouse guard` 是参考权限关口：拿凭证对照管理员表，用对应账号只执行固定命令，写审计日志，只放行真人发起的轮次（#1078、#1079、#1081）。
- **bothouse 页面变成 DSH 插件里的开关行。** 频道、团队工作台、bothouse 面板、其他电脑，在 DSH「插件 → bothouse」里各有一个开关。新装只开频道；老用户升级后侧栏保持原样（#1054）。

## 缺陷修复

- **Windows 更新后「打开 DSH」：** 桥没记下的 `dsh web`，令牌还能登录就接过来用，否则先结束它。gate 先于 DSH 启动，DSH 起得慢也不会让成员没有 gate（#1075）。
- **用户指定主角色，在单角色和只走 gate 的场景下也生效：** gate 在返回 503 和走单角色分支之前，先识别「你是主角色」（#1070）。

## 改进

- **CI：** `bothouse guard help` 和其他命令一样正常退出。升级测试改用 #1044 之后格式的频道配置，因为更早的会按设计被替换（#1082）。
