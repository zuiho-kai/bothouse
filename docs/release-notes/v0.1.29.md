## Highlights

- **Upload and crop member portraits.** Choose a local PNG, JPEG or WebP, frame a square crop and upload a 256×256 PNG. Portraits stay in the local data directory; existing members update immediately and can restore their default avatar (#527, thanks @HarunaRyo-051).
- **Choose a primary role and working directory per channel.** Workspaces inherit their parent channel. Channels without an override retain the global primary; saving a directory asks whether to recreate sessions now or keep existing conversations until the next new session (#527, thanks @HarunaRyo-051).
- **Read the task board as cards.** A dedicated dialog groups tasks by channel, workspace and owner, with four status tabs, dispatch/delivery links and a stable dialog height (#480, #514, thanks @HarunaRyo-051).
- **Hand the primary role to another member.** Manual handoff persists the task snapshot and subsequent changes, prepares the incoming primary and confirms only after its successful first turn (#274, #458, thanks @Zssan12).
- **QQ and QQBot routing carries conversation context.** QQ recognizes mentions, replies and direct messages; official QQBot supplies mention/direct/channel metadata and dispatches outside its read loop. Plain `@id` output from QQ members becomes a real mention segment (#344, #343, #475, #476, #506, thanks @Zssan12).

### Fixes

- **Channel task tracking follows the channel primary.** Dispatches, deliveries and acceptance use the channel selection while retaining legacy behavior for channels without an override (#527, thanks @HarunaRyo-051).
- **New channel members stay in that channel.** Adding from a workspace binds the member to its parent chat channel (#484, thanks @HarunaRyo-051).
- **Handoffs keep more actual conversation.** Repeated identity, team-rule, memory and delegation blocks no longer displace useful history in the handoff tail (#504).
- **Member edits preserve identity.** Backend switches, custom names and optional personas stay synchronized across setup, management and DSH; existing CLI instruction files are preserved. Adding a cloud-web member rejects typed duplicate names (#367, #460, #492, #493, thanks @Zssan12).
- **Unavailable Cursor backends report the cause.** Failed members show their backend error rather than silently appearing ready (#497, #500, thanks @Zssan12).
- **Task cards can be reclaimed by later turns.** A card released by an earlier turn can be claimed again for continued work (#517, thanks @Zssan12).
- **Relay watches remind before stopping.** The first timeout reminds the task owner; a later timeout stops work that remains idle (#501, thanks @Zssan12).
- **Accepted work resumes after an idle turn.** Deadline checks survive continuation; active delegated work and coordinator waits remain tracked across restarts. Delivered acceptances close correctly, and task-board owners remain watched (#528, #529, #530, #531).
- **Shutdown waits for the resume scan.** Engine shutdown waits for an in-flight turn-resume scan to finish (#494).
- **Packaged DSH UI retains channel renaming and personas.** The embedded client bundle includes the restored channel settings and member identity changes (#489, #522, thanks @Zssan12).
- **Core test compilation stays aligned with released watch and relay behavior.** Main/develop test repairs restore compilation and regression coverage (#487, #491, #472, thanks @Zssan12).

### Improvements

- **Archive completed Discord task threads automatically.** Terminal and result-ready task-card threads use a configurable archive delay (#498, thanks @Zssan12).
- **Configured teams bind automatically.** Relay team configuration seeds member bindings and the configured primary role (#462, #499, thanks @Zssan12).
- **Cleaner channel sidebar.** Channel settings, the task board and member controls have a clearer order and separators (#527, thanks @HarunaRyo-051).
- **QQ setup guidance is clearer.** Documentation explains joining a QQ group to DSH and corrects the earlier claim about official QQBot mention limits (#345, #502, #503, #505, thanks @Zssan12).
- **Upstream credit is explicit.** The README identifies cc-connect as the bridge upstream (#482).

## 重点

- **成员头像支持上传和裁切。** 选择本机 PNG、JPEG 或 WebP，调整方形取景后上传为 256×256 PNG。头像保存在本机数据目录；已有成员上传后立即更新，也可恢复默认头像（#527，感谢 @HarunaRyo-051）。
- **每个频道独立配置主角色和工作目录。** 工作区继承父频道设置，未覆盖的频道沿用全局主角色。保存目录后可选择立即重建会话，或保留当前对话、等下次新建会话再生效（#527，感谢 @HarunaRyo-051）。
- **任务板改为卡片。** 独立弹窗按频道、工作区和负责人分组，提供四个状态页签、派工与交回消息链接，切换页签时保持弹窗高度稳定（#480、#514，感谢 @HarunaRyo-051）。
- **支持手动交接主角色。** 持久保存任务快照和后续变化，准备新主角色的接手上下文，只有它成功完成第一轮后才确认交接（#274、#458，感谢 @Zssan12）。
- **QQ 与 QQBot 保留对话路由信息。** QQ 识别点名、回复和私聊；官方 QQBot 补齐点名、私聊与频道标识，并将派发移出读取循环。QQ 成员输出的纯文本 `@id` 会转换为真实点名（#344、#343、#475、#476、#506，感谢 @Zssan12）。

### 缺陷修复

- **任务板跟随频道主角色。** 派工、交回和验收使用当前频道的选择，未覆盖的频道保留原有行为（#527，感谢 @HarunaRyo-051）。
- **新成员绑定当前频道。** 从工作区添加时，成员归属其父聊天频道（#484，感谢 @HarunaRyo-051）。
- **交接保留更多真实对话。** 每轮重复的身份、团队规矩、记忆和派活指令块不再挤占交接尾部（#504）。
- **编辑成员保留身份。** 切换后端、自定名字和可选人设在向导、管理面板与 DSH 中同步，保留已有 CLI 指令文件；添加 cloud-web 成员时拒绝手填重名（#367、#460、#492、#493，感谢 @Zssan12）。
- **Cursor 后端不可用时显示原因。** 成员行展示后端失败信息，避免看起来已经就绪却无法回复（#497、#500，感谢 @Zssan12）。
- **后续轮次可重新认领任务卡。** 继续工作时，可以认领被之前轮次释放的任务卡（#517，感谢 @Zssan12）。
- **relay 看门先提醒再停止。** 首次超时提醒负责人，之后仍无进展才停止（#501，感谢 @Zssan12）。
- **已接任务停轮后继续推进。** 续做保留截止时间检查，重启后仍保留进行中的委派和协调等待；已交付的验收正确收口，任务板负责人持续受看门跟踪（#528、#529、#530、#531）。
- **停止引擎时等续做扫描结束。** 关闭流程会等待正在执行的会话续做扫描（#494）。
- **安装包中的 DSH 界面保留频道改名和人设。** 内嵌客户端重新同步频道设置与成员身份改动（#489、#522，感谢 @Zssan12）。
- **核心测试与已发布看门、relay 行为对齐。** 修复 main/develop 的测试编译并补齐回归覆盖（#487、#491、#472，感谢 @Zssan12）。
