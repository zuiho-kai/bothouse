## Highlights

- **JiuwenSwarm is found where it is installed.** The setup page's CLI step now looks for JiuwenSwarm the way it looks for Claude Code or DSH: on PATH, in the common install folders, in `pip --user`'s folder on macOS, and in the Python environment a running JiuwenSwarm was started from. When it is found, the card shows its version and whether the main process is up, and the launch command is filled in with the full path. When it is not found, the card says so, the form links the install steps, and **Next** waits until a command is given (#1936).
- **ACP agents come from a list, plus a card for any other one.** Agents that speak ACP and have no adapter of their own (JiuwenSwarm, OpenClaw, Trae CLI, COCO) are entries in one data list, so supporting one more is one more entry. A new **Custom agent (ACP)** card takes any launch command with its arguments, optional environment variables (`KEY=VALUE` per line) and an optional working directory (#1927).

## Fixes

- **The CLI step lists only what is on this machine.** OpenClaw, Trae CLI and COCO cards used to appear marked "not found" on machines without them. A list entry that is not found is now left out; JiuwenSwarm, the one supported by default, stays and shows its install link (#1941).
- **Grok's `agent` is no longer listed as Cursor.** Grok installs its CLI as `agent` and its help text mentions Cursor, so the Cursor row showed a Grok version. The check now reads the version line first (#1931).
- **No more "login unknown".** Antigravity and Cursor get a real login check. CLIs that have no check (Copilot, Kimi, Qoder, iFlow, Pi) say "signs in by itself on first start". A role with no known model shows no model text in place of an "unknown" placeholder (#1931).
- **A model with no price counts toward the spend cap.** A model missing from the price table was metered as zero, so its turns never reached the cap or the hand-in reminder. It is now charged at the highest rate in the table, and the warning names the model and the rates used (#1935).
- **A rework of a finished task takes one workspace.** Taking a finished task back for rework could claim two workspaces; the idle one was later reported as "no progress" and woken. Rework is now one command that continues in the workspace the task already holds, and the watch quietly ends a handoff whose task has left (#1923).
- **A refused nightly profile commit is reported and tried again.** When the commit of the nightly profile rewrite was refused, the rewrite was still logged as written and that time window was never read again. The pages are now put back and the same window is read the next night. A line that carries a forum tag stays in the current section (#1942).

## Improvements

- **A workspace that stops at "no improvement" explains itself first.** A report whose summary says the result did not help must state why the goal was not reached and what was tried next, whether this was fixed before, and whether the entry checked is the one the user uses. The kickoff text now tells a workspace to keep looking for the cause inside its scope (#1939).
- **The owner's profile is part of each role's instruction file.** The nightly profile rewrite also writes the owner's current section into each role's instruction file, and roles that carry it no longer get it pushed on every turn (#1942).

### Install

- **macOS 13 or later (Apple Silicon + Intel):** `bothouse-mac.dmg`
- **Windows:** `bothouse-windows.exe`
- **Linux:** `bothouse-linux-x64` (Intel/AMD) / `bothouse-linux-arm64` (ARM); `chmod +x`, then run.
- **Checksums:** `SHA256SUMS`
- **DSH plugin:** `npm i bothouse-dsh@0.1.82`

Already on v0.1.6 or later? Use the **Update to vX** button in the bottom-left corner. From v0.1.5 or earlier, download and install this release once. If an older updater times out, download and install this release manually.

macOS: drag **Bothouse.app** into Applications and **right-click → Open** the first time. Windows: if SmartScreen warns, click **More info → Run anyway**.

## 重点

- **JiuwenSwarm 装在哪就在哪找到。** 设置页选 CLI 这一步现在像找 Claude Code、DSH 一样找 JiuwenSwarm：PATH、常见安装目录、macOS 上 `pip --user` 的目录，还有正在运行的 JiuwenSwarm 所在的 Python 环境。找到时卡片显示版本和主进程是否已启动，启动命令自动填好完整路径。没找到时卡片直接说没找到，表单给安装步骤的链接，填了命令才能点 **下一步**（#1936）。
- **ACP 智能体走一份清单，其它的用自定义卡片接。** 讲 ACP、又没有专门适配的智能体（JiuwenSwarm、OpenClaw、Trae CLI、COCO）是同一份数据清单里的条目，多支持一种只加一条。新增 **自定义 Agent（ACP）** 卡片：填启动命令（含参数），可选环境变量（每行 `KEY=VALUE`）和工作目录（#1927）。

## 缺陷修复

- **选 CLI 这一步只列本机有的。** 以前没装 OpenClaw、Trae CLI、COCO 的机器上也会出现标着「没找到」的卡片。现在清单里没找到的不列；默认支持的 JiuwenSwarm 保留，并给出安装链接（#1941）。
- **Grok 的 `agent` 不再被认成 Cursor。** Grok 的命令行也叫 `agent`，帮助文字里又提到 Cursor，Cursor 那一行就显示成了 Grok 的版本号。现在先看版本那一行再认（#1931）。
- **不再出现「登录状态未知」。** Antigravity 和 Cursor 有了真正的登录检查。查不了的 CLI（Copilot、Kimi、Qoder、iFlow、Pi）写「启动后由 CLI 自己登录」。不知道模型的角色不显示模型文字，不再写「未知」（#1931）。
- **没有价格的模型也计入花费上限。** 价格表里没有的模型以前按零计，它的轮永远到不了上限，也收不到交结果的提醒。现在按价格表里最高的费率计，警告里写明是哪个模型、按什么费率（#1935）。
- **做完的任务返工只占一个工作区。** 把做完的任务拿回来返工时可能占到两个工作区，闲着的那个之后被报「没进展」并叫醒。现在返工是一条命令，在任务原来占的工作区里接着做；任务已经离开的交接，看护会安静地结束它（#1923）。
- **每晚画像改写的提交被拒会说出来并重试。** 以前提交被拒，日志仍记成已写入，那段时间窗也不会再读。现在把页面放回去，下一晚重读同一段。带论坛标记的行留在当前一节（#1942）。

## 改进

- **工作区停在「没提升」之前要先说清楚。** 汇报摘要里说结果没用的，必须写明为什么没达到目标、接着试了什么，以前修过没有，核对的入口是不是用户实际用的那个。开工说明也改成：结果没达到目标时在范围内接着找原因（#1939）。
- **主人画像进到每个角色的说明文件里。** 每晚画像改写时，也把主人当前那一节写进各角色的说明文件；已经带着它的角色不再每轮推送（#1942）。
