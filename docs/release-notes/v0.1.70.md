## Highlights

- **A handoff is not lost when the turn ends.** When a turn ends, the bridge closes the agent process. Before, that killed a `ws-handoff` still running, so the agent said "handed off" but the task never reached the board. Now `ws-handoff` and `ws-handoff --resume` run in their own session and finish even if the caller is killed; if they then fail, a short notice goes to the chat the task came from (#1692, #1694, #1693).
- **A question gets an answer, not an old job.** After a turn that broke off with an error, the next turn is told the old request is not its job: it answers the new message and asks at the end whether to continue. Members answer questions and chat directly; only real big jobs go to a workspace (#1697, #1698, #1699, #1701).

## Fixes

- **Handoff checks report everything in one pass**, so a handoff file is fixed once instead of resubmitted several times (#1697).
- **Workspace decisions and approvals:** a numbered workspace 【问】/【升】 keeps its full question and reply; one approval can be answered from the workspace or its parent channel; bridge buttons stay buttons; handoff source parsing stays in its own section (#1677, thanks @HarunaRyo-051).
- **Cooldown redelivery:** several messages recovering from a cooldown in one session all queue again (an exited process no longer blocks them), and background timer, cron and heartbeat turns no longer promise a retry in the channel (#1680, thanks @Zssan12).
- **Team-mode common-sense fixes, round two (#1492):** a failed wake-up no longer marks a task as handed off; a queued `ws-up --ask` no longer says it was posted; rework reports are deduplicated per handoff; a release that failed to save does not release the workspace; scan approvals close the board item; timers missed while the bridge was down are announced in their channel (#1682).
- **Task state cleanup (#699):** removed the last patch layers — the progress-step guard, read-failure counters, delayed workspace return, return-on-reset and matching handoffs by title; a workspace goes back to the pool on its handback event (#1695).
- **Lead switch record is sent once**, and parked workspaces are folded to a count with a `bothouse ctx` id, so a new session no longer carries tens of thousands of characters (#1700).

## Improvements

- Several single read-only lookups in a row are no longer blocked by the bash guard; the command runs with a reminder to combine lookups when it can (#1698).
- The fingerprint at the end of a folded block's title (for example 【常驻做法 3253b7】) can be passed to `bothouse ctx` to read the full text (#1698).
- Memory push marks inferred rows 【推论】, and nightly summaries tag each new line as fact, inference or guess (#1657).
- Start-of-work lesson reminders read split lesson tables, including their subpages (#1628).

## 重点

- **回合结束也不丢交接。** 回合结束时桥会关掉代理进程。之前还在跑的 `ws-handoff` 会被一起杀掉：代理说了「已交出」，活却没上任务板。现在 `ws-handoff` 和 `ws-handoff --resume` 在自己的会话里跑，调用方被杀也会跑完；之后真失败了，会在派活的频道发一句提醒（#1692、#1694、#1693）。
- **问一句就答一句，不带出旧活。** 上一轮出错中断后，下一轮会注明旧请求不是这一轮的活：先答新消息，末尾再问要不要接着做。副手遇到问话、闲聊直接答，只有真正的大活才交工作区（#1697、#1698、#1699、#1701）。

## 缺陷修复

- **交接检查一次报齐**，交接文件改一次就过，不再反复重交（#1697）。
- **工作区提问与审批：** 带编号的工作区【问】/【升】保留完整问题和回复；同一个审批在工作区和所属频道都能答；桥的按钮不再退化成纯文字；交接来源只在本节里解析（#1677，感谢 @HarunaRyo-051）。
- **冷却后重发：** 同一会话里多条冷却后的消息都能重新排队（已退出的进程不再挡住它们）；后台定时、cron、心跳轮不再在频道里承诺「冷却后自动重试」（#1680，感谢 @Zssan12）。
- **团队模式常识梳理第二轮（#1492）：** 叫醒失败时任务板不再写「已交接」；`ws-up --ask` 只是排上队时不再说已报回；返工汇报按这次交接判重；释放工作区存盘失败就不释放；扫描放行也关任务板条目；桥停机错过的定时，标过期时在原频道说一句（#1682）。
- **任务状态清理（#699）：** 删掉最后几层补丁——进度步守卫、读失败计数、延时放回、重置即放回、按标题对交接；工作区在交回事件时放回池子（#1695）。
- **换主交接只发一次**，已暂停的工作区折成条数加 `bothouse ctx` 编号，新会话不再多带几万字（#1700）。

## 改进

- 连续几步单条只读查询不再被 bash 守卫拦下：命令照跑，附一句能合并就合并的提醒（#1698）。
- 折叠块标题末尾的指纹（如【常驻做法 3253b7】）可以直接交给 `bothouse ctx` 取正文（#1698）。
- 记忆推送给推论行标【推论】，夜间总结给新写的每条标事实、推论或猜测（#1657）。
- 开工的教训提醒能读拆分后的教训表，包括子页（#1628）。
