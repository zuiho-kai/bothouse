## Highlights

- **The chat lead gets woken instead of having to remember.** When a task stops, gets stuck, or a channel's board runs out of work, the bridge queues a turn for that channel's lead with the item number and where it stopped. The last case is `keep_running` (on by default; `board keep-running on|off` per channel) and fires once per batch of work. Wakes wait while you are talking to the lead. (#2206, #2209)
- **A task's messages go where the task lives.** Ownership is set once when the task is created, and every outgoing path — reports, watch notices, passes, forwards, task posts, replies — asks the board for it; a message whose item has no owner stops instead of quietly falling back to another channel. `bothouse send --for <id>` goes to the owner directly, and `--cross-channel` is needed to send anywhere else. Old rows can be repaired with `board move` or the one-off `board backfill-owner`. (#2212, #2213, #2214)
- **Every CLI gets the same bridge instructions.** Codex, Gemini/Antigravity, DSH and ACP agents now receive the same rules Claude gets, including sending generated files with `bothouse send --file` instead of a local path. (#2196)

## Fixes

- **Windows: no stray console windows, fewer missed retries, one data directory.** Child processes the bridge starts no longer open a console window; the retry list covers the error lines machines outside ours actually print; and DSH no longer creates a second data directory on installs that only have the old one. (#2197, #2201)
- **A fresh setup-only install can save its first project.** Adding a manual platform returned HTTP 503; it now saves and reads back. Thanks @Ray0766. (#2182)
- **A report is accepted by the dispatcher that wrote the work, in its chat session**, and a handoff line that narrows the requested scope without backing is rejected. (#2193, #2198)
- **No false "stopped" notice** when a report is sent back or a task is re-dispatched within a minute, or while a report waits for the lead. (#2199)
- **Watch steps stay out of the user's chat**, and a wait for an outside blocker runs until that blocker's own clock, up to 7 days. (#2195)
- **Videos carry a version line before each file**, and Chinese filenames no longer collapse to `--A--Discord.mp4`; `bothouse send` gained `--board-id` and `--label`. (#2202)
- **Another task's deliverable can't be attached as this one's**: the send is refused with the owner task named. (#2208)
- **A Discord reply that writes `@name` now notifies that person**: once they have spoken in the channel, the name becomes a real mention; code blocks are left alone. Thanks @Zssan12. (#2176)

## Improvements

- **A follow-up task can be tied to the item it continues** with `ws-handoff --follow <id>`, so its reports and passes return to that item's channel; `board move` changes an owner and leaves a trail. (#2214)

## 重点

- **主角色会被叫醒，不用自己记着回来看。** 一件活停了、卡住了，或一个频道的活都做完、都停下了，桥会给那个频道的主角色排一轮，带上编号和停在哪。最后一种叫 `keep_running`（默认开，单个频道用 `board keep-running on|off` 改），一段活只叫一次。你正在和主角色说话时先压住。 (#2206、#2209)
- **一件活的消息回到这件活自己的频道。** 归属在建活时定一次，之后交回、看门通知、放行、转话、任务帖、回复都向任务板要这一个归属；条目没有归属就停住，不再悄悄换下一个频道。`bothouse send --for <编号>` 直接发到归属频道，发别处要加 `--cross-channel`。旧条目用 `board move` 改，或用一次性的 `board backfill-owner` 补。 (#2212、#2213、#2214)
- **所有 CLI 拿到同一份桥说明。** Codex、Gemini/Antigravity、DSH、ACP 现在和 Claude 收到同一套规则，包括用 `bothouse send --file` 发文件而不是给一个本地路径。 (#2196)

## 缺陷修复

- **Windows：不再弹控制台窗口，重试名单补齐，数据目录只认一个。** 桥起的子进程不再新开窗口；重试名单收进了外部机器真会打出来的报错句；只有旧数据目录的装法不会再被建出第二个目录。 (#2197、#2201)
- **全新装在「只设置」模式也能保存第一个项目。** 手动加平台原来回 503，现在能存下、能读回。谢谢 @Ray0766。 (#2182)
- **派活人自己写的活，交回由它在聊天里的会话验收**，不再绕回工作区；交接里没有依据就缩小范围的句子会被拒。 (#2193、#2198)
- **不再发假「停了」**：交回被马上打回续派、暂停不满一分钟、或汇报在等主角色验收时，都不报停。 (#2199)
- **看门的催促不进用户的聊天**；等外部原因的，按外部那个时间点等到，最长七天。 (#2195)
- **每条视频前有版本说明**，中文文件名不再变成 `--A--Discord.mp4`；`bothouse send` 加了 `--board-id` 和 `--label`。 (#2202)
- **别的活的成品不能当这件活的附件发**：会被拒，并说出它属于哪件活。 (#2208)
- **Discord 回复里写 `@名字` 现在真能提醒到人**：对方在这个频道说过话之后，名字会转成真 at；代码块里不动。谢谢 @Zssan12。 (#2176)

## 改进

- **续办的活可以挂到它接着的那件活上**：`ws-handoff --follow <编号>`，交回和放行回到那件活的频道；`board move` 改归属并留痕。 (#2214)
