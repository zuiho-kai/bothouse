It works right after install. The task board, progress cards, workspaces, the 10-minute watch and memory all show up by themselves. With only one role, too.

## Task board and task cards

- **One role gets the full set.** A single-role install now also has the pinned task board, the team directory and workspaces. Before, you needed two or more roles (#372).
- **The self-hosted web chat has a task board.** The room has only one task board message. It is updated in place and does not flood the room (#378).
- **Feishu has task cards and a pinned task board.** Task cards are updated in place, and updates are posted as replies under the card. A deleted card is sent again. Errors that cannot be fixed by retrying, such as missing permissions, are no longer retried again and again (#374).
- **Finished tasks show "Done".** The completion record no longer says "In progress" (#402).
- **The task board of the self-hosted web chat lists the real items.** Items in progress, items in each workspace, paused items and items finished today are listed apart. The card status follows what really happens and no longer stays at "In progress" (#386).

## Workspaces

- **The DSH lead role can open workspaces by itself.** After a workspace is open, the handoff message is posted into it, and the task goes into the 10-minute watch. The same task in the chat channel moves to the workspace, so you are not reminded twice (#409).
- **Questions and reports from self-hosted web workspaces go to the main chat channel.** The user answers with the number, and the answer goes back only to the role that asked. A question without its self-check result or category is sent back to be completed (#390).
- **When Discord permissions are missing, the hint says how to add them.** When the bot is already in the server, tick the permissions on its role in the server settings. Opening the invite link again does not update the permissions (#394).
- **Discord invite links include the permissions team mode needs.** A newly invited bot can create workspaces and pin the task board. When a permission is missing, the error says whether it is "Manage Channels" or "Manage Messages" (#385).

## 10-minute watch

- **The watch starts with the app.** You do not wait for someone to turn it on. After a config reload, the watch moves over to the new config (#373). Retries no longer push the start of the timer later (#368).
- **Tasks handed to teammates go into the watch too.** New progress extends it by 10 minutes, up to two times. With no progress, it sends one nudge on the task card and collects the work done so far (#403).
- **Nudges in self-hosted web workspaces are delivered.** Before, they were not sent (#406).

## Memory

- **The lead role writes to the main wiki directly.** Its sessions are imported into the main wiki automatically, and search also uses the main wiki. Teammates still each have their own role wiki (#397).
- **Each turn searches memory in the main wiki and the role's own wiki.** It does not search other roles' wikis (#396). The role wikis of DSH members can now be searched too (#400).
- **A task handed to a teammate includes her own memory index on the first turn.** Related wiki pages are included too (#391).
- **DSH members also get related wiki pages and the task board each turn.** The same as bots on the other platforms. With only DSH installed, the memory service also starts by itself (#379).
- **A main wiki made by the wizard has scheduled cleanup and export set up by default.** Self-hosted web installs have it too. Your existing wiki is not written to (#407).
- **Running the wizard again makes the main wiki even when you add no new role.** When a step is skipped, the reason is shown (#395).

## Teamwork

- **Teammates made by the wizard can hand tasks to each other without manual binding.** It works in any channel on that platform. To leave a member out, you can still remove it by hand (#393).
- **Roles need no manual environment setup.** Each turn carries the data folder, the task board location and the tool paths, so collaboration commands work by name (#369).
- **The lead role can read the playbook.** It is now read from where it is installed (#370).
- **The team file records each member's platform identity and working folder.** The collaboration tools use only this file (#376).
- **Two roles on the same CLI do not share a folder.** The wizard checks this before it writes any config, and the error names the two roles (#375).

## Install and login

- **Two bothouse installs on one machine do not clash on ports.** A port in use is replaced with a free one automatically. Also with only DSH installed (#389, #401).
- **claude and codex are found even when they are not on PATH.** When they are installed in a common folder, they are found and started automatically (#384).
- **The self-hosted web chat downloads uv when it is missing.** On the first start, it downloads uv, Python and the dependencies by itself. This takes about one or two minutes (#388).
- **A token from `claude setup-token` counts as logged in.** The wizard and DSH members both accept it (#394, #401).
- **Codex roles work in a fresh environment.** At start, the role folder is trusted automatically. A folder you set as not trusted is not changed (#392).
- **After a DSH CLI member clicks "Allow all", the session asks no more (#408).**

安装好就能用。任务板、进度卡、工作区、十分钟看门、记忆，这五样会自己出现。一个角色也一样。

## 任务板和任务卡

- **只装一个角色，也有全套。** 单角色安装现在也有置顶任务板、团队目录和工作区。以前要装两个以上角色才有（#372）。
- **自建网页有任务板了。** 房间里只有一条任务板消息，原地更新，不刷屏（#378）。
- **飞书有任务卡和置顶任务板了。** 任务卡原地更新，进展以回复发进卡片下面。卡被删了会重发。缺权限这类修不好的错误不再反复重试（#374）。
- **做完的任务显示「已完成」。** 完成记录里不再留着「进行中」（#402）。
- **自建网页的任务板列出真实条目。** 在做的、各工作区的、暂停的、今天做完的，都分开列出来。卡片状态跟着实际情况变，不再一直显示进行中（#386）。

## 工作区

- **DSH 的主角色能自己开工作区。** 开好后，交接消息自动发进去，活自动进十分钟看门。聊天频道里同一件活会转到工作区，不会提醒两次（#409）。
- **自建网页的工作区，提问和汇报会转到主聊天频道。** 用户带编号回答，答案只送回提问的那一位。提问没写自验结果或类别，会被退回去补（#390）。
- **Discord 缺权限时，提示说清楚怎么补。** 机器人已在服务器里时，要去服务器设置的身份组里勾权限。重开邀请链接不会更新权限（#394）。
- **Discord 邀请链接带上团队模式要的权限。** 新邀请的机器人能建工作区、置顶任务板。缺权限时，报错写明缺的是「管理频道」还是「管理消息」（#385）。

## 十分钟看门

- **看门跟着程序一起启动。** 不用等谁来开。重载配置后，看门跟着换过去（#373）。重试不再把计时起点往后推（#368）。
- **派给队友的活也进看门。** 有新进展就续 10 分钟，最多续两次。没进展就在任务卡上催一次，收回已有的半成品（#403）。
- **自建网页工作区的催促能发出去了。** 以前发不出（#406）。

## 记忆

- **主角色直接写主 wiki。** 她的会话会自动导进主 wiki，检索也查主 wiki。队友照旧各有自己的角色 wiki（#397）。
- **每轮查记忆，查主 wiki 和自己的角色 wiki。** 不查别人的（#396）。DSH 成员的角色 wiki 现在也查得到（#400）。
- **派给队友的活，第一轮附上她自己的记忆目录。** 还附上相关的 wiki 页（#391）。
- **DSH 成员每轮也拿到相关 wiki 页和任务板。** 和其他平台的机器人一样。只装 DSH 时，记忆服务也会自己起来（#379）。
- **向导建的主 wiki，默认挂好定时整理和导出。** 自建网页安装也有。你原有的 wiki 不会被写入（#407）。
- **重跑向导时，没加新角色也会补建主 wiki。** 跳过某一步时会写明原因（#395）。

## 团队协作

- **向导建的队友之间，互相派活不用手动绑定。** 在该平台任意频道都能派。想排除某个成员，照旧可以手动去掉（#393）。
- **角色不用手配环境。** 每一轮都带好数据目录、任务板位置和工具路径，协作命令按名字直接用（#369）。
- **主角色能读到工作手册。** 现在从安装的位置读（#370）。
- **团队文件记下每个成员的平台身份和工作目录。** 协作工具只认这一份（#376）。
- **同一个 CLI 开两个角色，目录不会撞。** 向导在写任何配置之前就检查，报错写明是哪两个角色（#375）。

## 安装和登录

- **一台机器装两套 bothouse，端口不会撞。** 被占就自动换一个空闲端口。只装 DSH 时也一样（#389、#401）。
- **claude 和 codex 不在 PATH 里也能找到。** 装在常见目录里的，会自动找到并启动（#384）。
- **自建网页缺 uv 时会自动下载。** 第一次启动时，会自己下载 uv、Python 和依赖，大约一两分钟（#388）。
- **用 `claude setup-token` 的令牌登录也算已登录。** 向导和 DSH 成员都认（#394、#401）。
- **Codex 角色在全新环境下也能直接用。** 启动时自动信任角色目录。你自己设成不信任的，不会改（#392）。
- **DSH 的 CLI 成员点「允许所有」后，本次会话不再弹确认（#408）。**
