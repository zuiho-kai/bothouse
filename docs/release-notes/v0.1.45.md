## Highlights

- **QQ group turns keep their context without turning it into commands.** Paragraph bubbles are opt-in, the group-member allow list can be extended, original images are stored with bounded previews, and recent, quoted and forwarded messages are attributed to their senders; command, permission and stop routing still read the raw sender text. An optional judging model (off by default) can answer turns that are neither a clear command nor a clear mention: it supports a self-hosted OpenAI-compatible endpoint, a remote API whose credential comes from an environment variable, and a custom HTTP endpoint, and stays silent when the decision is unclear or the model fails (#752).
- **Each channel keeps its own model and reasoning effort.** Changing one channel's model no longer rewrites the shared agent or project defaults; the choice is persisted per execution session and handed to each adapter at startup, so two channels can run different models and efforts at the same time and keep them after the engine is rebuilt. Directory defaults remain the fallback (#840).
- **Memory and guard hooks can be installed once for the whole machine.** The setup wizard and `bothouse setup hooks --global` gain two optional items, both off by default: memory (relevant wiki pages on every message and end-of-session ingest for every Claude Code session) and guard (the Claude Code role guard in `~/.claude/settings.json` plus the long-task agent). Hooks the bot or project already installs are not duplicated, and turning the options off restores the previous file byte for byte after a backup (#850).
- **The progress prompt costs one line per turn.** A turn only carries `[在做] <title>` when a task is open, instead of the whole journal, member and artifact guide (about 1.3k tokens); the full guide moved to `bothouse progress --help`, and voice turns now register the run token so `bothouse progress` works there too (#860, #861).
- **Claude Code sessions no longer report themselves as `sdk-cli`.** They use a bothouse entrypoint, avoiding the one Anthropic's issue tracker shows burning the five-hour window about 1.8–2.5× faster per token; `BOTHOUSE_CLAUDE_ENTRYPOINT` overrides it (#859).
- **Task acceptance and paused queues are closed up.** A handback waits for acceptance and is chased on the ten-minute watch, falling back to the lead when nobody is assigned; the board shows the last real progress and marks an hour without progress as stuck; a paused task keeps its queue position and resumes there (#830). A late report is bound only to the task it names, so a reused workspace no longer applies it to the new task or resets its session (#831).
- **Reinstalling no longer drops the delivery and handoff checks that came with the install.** The bundled contrib sources now carry the requirement sheets, attachment checks and the sourced headquarters judgment used by handoffs (#858).

## Fixes

- **`ws-forward` is no longer mistaken for status polling.** A one-minute forwarded prompt that mentioned "status", "receipt" or "quota" was rejected by the anti-spin guard, so the handoff file looked delivered while the workspace was never woken; forwarded jobs now carry a trusted one-shot marker and pass, for both normal and `--interrupt` forwards (#838).
- **Timers queued after a restart no longer answer "message received".** One-shot, cron and heartbeat turns that wait in the queue skip the receipt, and a paused task is no longer reminded twice in the same round by the paused-question pass and the roundup (#855, #856).
- **A first-turn workspace report that the delivery check bounces is no longer lost.** When no repair turn can follow, it is forwarded to the chat channel with a `系统核对` line, and both the bounce and the refused authorization are logged (#849).
- **`intent_judge` checks the wiki before judging a start-authorization question.** A question like "should I start" that matches a recorded "give me a plan first" decision is passed instead of blocked; no wiki or a search error keeps the old behaviour (#834).
- **DSH installs resolve their own packages.** The web app, `ws` and `yaml` are resolved from the running DSH and from collab's own `node_modules` instead of being borrowed from another install, an ordered patch array is applied in order, and a DSH that is missing its own web app fails with a clear error (#847).

## Improvements

- **A handoff that says `无（新建）` must list what was surveyed for reuse** — which existing capability was checked and why it does not fit (#841).
- **QQ outbound sends leave a structured receipt:** pid, project, session, inbound and outbound message ids, action and a content summary, so a doubled send can be traced back to the turn that caused it (#843).
- **Tests:** the QQ blank/cancelled-send reproductions and the team wake-limit test follow the new behaviour (#820, #851).

## 重点

- **QQ 群里的上下文不再被当成命令。** 气泡段落可开、群成员白名单可扩展，原图会保存并生成有上限的预览，最近消息、引用和转发都带上说话人；命令、权限和停止的判定仍然只读发送者原文。可选的判断模型（默认关）处理既不是明确命令、也不是明确 @ 的轮次：支持自建的 OpenAI 兼容接口、凭据放在环境变量里的远程接口和自定义 HTTP 接口；判不准或模型出错时保持安静（#752）。
- **每个频道有自己的模型和推理强度。** 改一个频道的模型不再改写共享的 agent 和项目默认值；选择按执行会话保存，启动时作为固定快照交给各适配器，两个频道可以同时跑不同的模型和强度，引擎重建后也还在。目录里的旧默认值仍作兜底（#840）。
- **记忆和守门只装一次，全机可用。** 安装向导和 `bothouse setup hooks --global` 多了两个可选项，默认都关：记忆（每条消息附相关 wiki 页、会话结束自动整理，覆盖本机所有 Claude Code 会话）和守门（把 Claude Code 角色的守门 hook 装进 `~/.claude/settings.json`，long-task agent 放进全局 agents）。bot 会话或项目里已装的同名 hook 不会重复；关闭时先备份，只删 bothouse 加的部分，全删光时逐字节还原原文件（#850）。
- **进度提示每轮只剩一行。** 只有手上有活时才带 `[在做] <标题>`，不再每轮塞进整套进度日志、成员和产物说明（约 1.3k token）；完整用法移到 `bothouse progress --help`，语音轮也会登记 run token，语音会话里 `bothouse progress` 同样可用（#860、#861）。
- **Claude Code 会话不再自报 `sdk-cli`。** 改用 bothouse 入口，避开 Anthropic 议题里记录的、同样工作每 token 烧五小时窗口快约 1.8–2.5 倍的那条路径；可用 `BOTHOUSE_CLAUDE_ENTRYPOINT` 覆盖（#859）。
- **任务验收和暂停队列收口。** 交回后进入待验收，沿十分钟看门周期催验收，没配验收人就转主角色；任务板按最后一次真实进展显示，一小时没进展标为卡住；暂停的活保留队位，恢复和答复续办都按原队列接上（#830）。迟到的报告只绑它明确写的任务，复用工作区不再把旧报告安到新任务头上，也不会重置新任务的会话（#831）。
- **重装不再丢掉随包安装的交付和交接检查。** 随包发布的 contrib 源码补回了需求单、附件检查和交接必须引用总部判断的那套规则（#858）。

## 修复

- **`ws-forward` 不再被当成状态轮询。** 一分钟的转交提示里只要带「状态」「回执」「额度」这类词，就会被 anti-spin 拒收，交接文件看着已转、工作区其实没被叫醒；现在转交任务带一个受信的一次性标记直接放行，普通转交和 `--interrupt` 紧急转交都覆盖（#838）。
- **重启后排队中的定时轮不再回「消息已收到」。** 一次性、周期和心跳轮次在队列里等待时都不发排队回执；同一件暂停的活也不会在同一轮被 paused-question 和整点汇总各提醒一次（#855、#856）。
- **首轮被交付核对退回的工作区报告不再丢。** 没有可重交的回合时，照常转到聊天频道并附一行「系统核对：…」，退回和授权拒发都补了日志（#849）。
- **`intent_judge` 判开工授权题前先查 wiki。** 「要不要开工」这类问题命中用户定过的「先给方案」时直接放行，不再误拦；没有 wiki 或搜索出错时保持原来的行为（#834）。
- **DSH 安装只解析自己那份包。** web 应用、`ws` 和 `yaml` 从正在运行的 DSH 和 collab 自己的 `node_modules` 解析，不再借用别的安装；补丁数组按上游顺序依次应用；DSH 缺自己的 web 应用时直接报清楚的错（#847）。

## 改进

- **交接写 `无（新建）` 时必须附「复用盘点」，** 写清查过哪些现成能力、为什么不能用（#841）。
- **QQ 出站留下结构化回执：** pid、项目、会话、入站和出站 message_id、动作和内容摘要，重复发送能追回到触发它的那一轮（#843）。
- **测试：** QQ 空白/取消发送的复现和团队唤醒上限测试跟上了新行为（#820、#851）。
