## Highlights

- **Roles know their memory is on.** Every session now gets a short note, built from the real switches, saying which memory features are on: the shared memory wiki, nightly reflection and the memory forum. Asked "is the LLM wiki / memory forum on?", a role answers yes and can search it on the spot instead of saying it has none. This works for every CLI through gate. Old installs get the wiki-ingest and forum nightly-settlement cron jobs added once at startup (#1059).
- **A directly named sub hands big jobs to a workspace too.** The team rules now say whoever takes a big job writes the handoff, not only the lead. When Discord refuses to create a workspace channel, the error names the missing "Manage Channels" permission and where to grant it (#1060).

## Fixes

- **Memory votes use the right id.** The capability note and the per-session vote reminder say only the 10-hex ids of decisions and lessons can be voted; `memvote` explains when it gets an 8-hex `ctx` id instead of only printing usage (#1062, #1063, #1068).
- **A Stop-hook-blocked draft is no longer sent with its rewrite.** Without tool progress, only the rewritten reply goes out (#1058).
- **Restarting the bridge no longer deletes and re-posts every channel's task board.** The lead keeps its pinned boards and edits them in place (#1064).

## Improvements

- **CI test expectations follow the memory-env and team-rule wording changes** (#1065).

### Install

- **macOS (Apple Silicon + Intel):** `bothouse-mac.dmg`
- **Windows:** `bothouse-windows.exe`
- **Linux:** `bothouse-linux-x64` (Intel/AMD) / `bothouse-linux-arm64` (ARM); `chmod +x`, then run.
- **Checksums:** `SHA256SUMS`
- **DSH plugin:** `npm i bothouse-dsh@0.1.50`

Already on v0.1.6 or later? Use the **Update to vX** button in the bottom-left corner. From v0.1.5 or earlier, download and install this release once. If an older updater times out, download and install this release manually.

macOS: drag **Bothouse.app** into Applications and **right-click → Open** the first time. Windows: if SmartScreen warns, click **More info → Run anyway**.

## 重点

- **角色知道自己的记忆开着。** 每个会话都会收到一段按实际开关生成的说明，写明开了哪些记忆能力：共用记忆 wiki、夜间反思、记忆论坛。被问「llm wiki / 记忆论坛开了吗」，角色答开了，还能当场查，不再说没有。所有 CLI 都经 gate 生效。老安装启动时一次性补上 wiki 整理和论坛夜间结算两个定时（#1059）。
- **副手被直接点名接大活，也交给工作区。** 团队规矩改成谁接活谁写交接，不只主角色。Discord 拒绝建工作区频道时，报错写明缺「管理频道」权限、去哪加（#1060）。

## 缺陷修复

- **记忆投票用对编号。** 能力说明和每会话的投票提醒都写清：只投定案、经验条的 10 位编号；`memvote` 收到 8 位取正文编号时直接说明，不再只打用法（#1062、#1063、#1068）。
- **Stop hook 拦下的初稿不再和重写版一起发出。** 不显示工具进度时，只发重写后的回复（#1058）。
- **重启桥不再删掉再重发各频道任务表。** 主角色保留置顶的任务表，原地更新（#1064）。

## 改进

- **CI 测试期望跟上记忆环境变量和团队规矩文案的改动**（#1065）。
