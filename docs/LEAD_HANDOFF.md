# 主角色手动交接（#274）

旧主 bot 已经不能回话，或者你要主动换一位主角色时，用这条命令把团队记录交给新主：

```sh
bothouse handoff status
bothouse handoff show
bothouse handoff switch --to <新主项目名>
```

`status` / `show` 直接读本机持久记录，bridge 没在跑也能用；`switch` 必须连到正在运行的本地 bridge（Unix socket），由它校验目标、写 `lead.json` 并让所有引擎在下一轮换主。

这不是 #47 的自动额度探测，也不会自动回切。手动切回旧主是允许的；是否切回由人决定。

## 切换时保留什么

切换记录写在 `<data_dir>/lead-handoff.json`。记录不依赖旧主再生成一段总结，来源是 bothouse 已经持久化的公开记录：

- `public-progress/<project-hash>/*.json` 的任务卡：标题、状态、事实阶段、要求/约束、最近进展、下一步、已有结果、验证证据、成员及状态、未完成投递、最近关键事件和任务 ID/来源路径。
- `team_workspaces.json` 的工作区交接：哪个聊天频道、哪个工作区、任务、负责人、开始/下次检查时间、是否暂停。
- `team-asks/*.json` 的待回答 `[ask]`：哪个 bot、哪个工作区、父频道、问题正文。
- `lead.json`：当前选中的项目与显示名、选择时间。

`lead-handoff.json` 记录切换双方、切换时间、状态（进行中 / 已生效 / 失败 / 已被下一次切换取代）、确认时间和失败原因，并保存一份切换时的快照。快照是交接证据，不是任务卡本身；任务卡的后续变化仍写回原任务。

## 新主什么时候看到

新主在自己的聊天频道下一次收到消息（普通消息、定时器或队列里的回合都算）时，bridge 在用户内容前附上交接记录。第一次给完整记录；同一 agent 上下文之后只补“交接后更新”，避免每轮重复。记录不会注入工作区频道，也不会改变平台权限、`allow_from` 或工具审批。

记录里的规则会写清：

- 已派出的活继续按原任务 ID 等结果，不重新派一遍；
- 未验证的结果不是已完成；
- 旧主的迟到消息只留存，不再有协调权；
- 工具审批绑定旧会话，不迁移、不会自动批准；
- 旧主 CLI 内部 session、隐藏状态和运行中的工具进程不在交接范围。

## 切换期间和之后的结果

任务卡和成员报告在切换期间照常写入。新主第一次收到完整记录时会带上切换后产生的新事件；确认接手后再产生的结果，会在新主下一轮以“交接后更新”出现，并保留原任务 ID。切换不会重跑结果未知的操作，也不会清空原有任务。

## 失败与重试

- 目标 bot 未接入、已停止，或 `lead.json` 写失败：不改变当前主角色，只在 `lead-handoff.json` 追加一条失败记录，并提示“任务和交接记录已保留，请重试或选择其他成员”。
- 新主的下一轮没有成功发生：记录保持“进行中”，不会误报“已生效”。可以再次 `handoff switch` 到同一位，或换一位成员。
- 连续切换：新记录取代旧记录；旧记录标记“已被下一次切换取代”，不会被旧主重新激活。
- 服务重启：`lead-handoff.json`、任务卡、工作区与 `[ask]` 都在磁盘上，重启后新主仍能收到；不会因为进程重启丢掉交接。

## 旧主迟到

`lead.json` 是每个回合重新读取的共享选择。切换后旧主的消息仍可能到达平台，但：

- 后续路由以新主为准，旧主不会因为旧回合或迟到回复重新成为主角色；
- `task assign` / `task accept` 这类协调动作会被拒绝，错误明确写出当前主角色；
- 成员的报告和结果不受这条限制，仍按原任务 ID 记录，避免切换时丢结果。

## 不包含什么

- 不迁移任何 CLI 的内部 session、上下文或工具进程；新主用自己的 CLI 会话接续任务层记录。
- 不自动探测额度、不自动回切、不自动重跑；切换是人工动作。
- 不把任务卡、工作区或 `[ask]` 之外的私聊、隐藏状态或原始工具日志复制进交接。
- 不给新主增加权限，也不改变旧主未决工具审批的状态。

## 验证覆盖

自动化测试覆盖：重复切换、旧主离线时切换、目标不存在/已停止、服务重启后再次注入、切换期间与切换后结果关联、旧主协调动作被拒、工作区不注入，以及 claudecode/codex 两种后端共用同一记录。真实入口验证使用编译后的 CLI 对隔离 `data_dir` 执行 `handoff status/show`，并用本地 Unix socket 的 `switch` 入口验证，不连接生产配置、不重启服务、不发真实频道消息。
