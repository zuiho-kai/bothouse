# #816 工作区交接与任务状态一致性

任务板的新绑定可能没有相应的新交接记录。此前按工作区、来源聊天与绑定时间取最近交接，未核对任务身份，因此会用旧任务的暂停或结束状态判定新任务。

本次在任务板投影边界核对交接 Board ID；旧格式没有 ID 时核对任务标题。绑定前已经结束的交接不能代表本次续接。没有匹配证据时保留任务板自身状态，显式暂停仍有效。没有改变 Park/Release 对历史交接的选择语义，也不会按模型忙闲强制取消暂停。

另一个确定的缺口在 ws-handoff 固定工作区入口：此前直接建板、唤醒，跳过共享池入口已有的 claim。现在先调用同一 claim 命令，拒绝时不建板、不唤醒；唤醒失败走既有撤板和释放路径。现场当时具体使用哪个派活入口无法从现有日志确认，不把该缺口描述为已证实的现场写入成因。

## 验证

- 修改前 Go 隔离回归：旧任务已暂停、新任务重新绑定同工作区，被判为“工作区已释放，任务暂停”。
- 修改前 Python 真实 main 入口（桥和存储边界替身）三个回归失败：缺少 claim、拒绝未中止、唤醒失败未释放。修改后通过。
- 覆盖当前活跃、真正暂停、无关任务延迟暂停/关闭、同任务释放后续接、旧格式标题匹配、无身份记录及显式任务板暂停。
- 状态、工作区及 CUJ 目标测试通过。全量与独立复核结果以 PR 为准。

没有修改生产状态、配置或工作区，没有部署。历史缺失的认领记录不会凭空补写；本次修正投影和之后的固定入口交接，不抢占正在运行的工作区。
