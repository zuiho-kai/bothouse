# 主动跟进授权

主动规则用于管理员明确允许的来源流。安装软件不会自动启动主动接单；不存在策略时，原有聊天路由保持不变。安装策略后，只有匹配已绑定账户、来源、会话及事件规则的未点名、非私聊、非命令消息进入推断候选检查；未匹配消息仍走原聊天路由。明确请求仍走原权限路径，点名不能提升工具权限。

## 模式与入口

| 模式 | 推断候选行为 |
| --- | --- |
| off | 不受理主动任务 |
| observe | 保存本地决策，匹配项为 would_accept；不启动执行者、不发确认、不执行候选工具 |
| auto | 仅匹配来源、绑定账户、会话与事件种类的候选受理为任务 |

off/observe 只限制推断型主动任务，不禁用普通聊天。匹配消息记录决策后仍经过原有路由、门闸及权限检查；普通回复不携带主动授权，也不会因此创建主动任务。明确用户请求保留原有检查。

当前规则是确定性匹配，不调用评估模型，不新增预算。`event_kind: message` 匹配指定账户在指定会话的未点名消息流，**不解析“审核已通过”等自然语言条件**；先用 observe 核对实际候选，再决定是否允许该消息流自动执行。不要把普通群聊的全部无人点名消息当作已授权工作。

Discord、QQ、飞书、cloud-web 的注册平台回调共用准入规则。适配器原有账户/频道过滤仍生效，被适配器过滤的消息不会进入观察。身份使用平台名和稳定账户 ID，不使用昵称；跨平台同一人需要管理员分别绑定。机器人、仅上下文及指向其他角色的候选不升级成主动授权。平台账户归属依赖可信适配器与管理员绑定，不能证明账号背后一定是自然人。

多路 bridge 入口使用适配器注册的远端平台作为账户命名空间。仅持有服务令牌的当前已注册适配器、在本次入站回调明确提供 from_bot 分类时，才可证明该候选来自可信适配器；省略分类、无令牌开发模式或重建的回复句柄不能获得主动授权。分类来自可信适配器，不是任意公开 webhook 的自证。

本地 ReceiveMessage、定时器、wiki、gate 输出不因此获得平台认证。外部 task_events 即使带 task_id 和有效 webhook 凭据，也始终只作为已有任务上下文；凭据认证入口，不认证载荷声称的真人身份。

## 管理接口

复用已配置管理服务及其鉴权；没有管理令牌时拒绝这些接口。根路径为 `/api/v1/projects/{project}/authorization`，返回沿用管理 API 的响应格式。

| 方法与相对路径 | 用途 |
| --- | --- |
| GET 根路径 | 查询私有策略、决策、分配、撤回及动作记录 |
| GET /policy | 取得当前策略及 version |
| PUT /policy | 用读取到的 version 替换策略；冲突返回 409 |
| POST /revoke/{decisionID} | 撤回指定决策 |
| POST /renew/{taskID} | 按当前策略重新评估原任务身份与原范围，保留同一任务 |

PUT 请求示例中的版本必须替换为 GET 返回的当前值；账户与会话也必须替换为本机已核对的真实标识。示例仅观察，不是默认配置：

```json
{
  "version": 0,
  "mode": "observe",
  "bindings": [
    {
      "principal": "review-owner",
      "identities": [{"platform": "discord", "user_id": "VERIFIED_ACCOUNT_ID"}]
    }
  ],
  "rules": [
    {
      "id": "review-followup",
      "source": "discord",
      "principal": "review-owner",
      "session_key": "VERIFIED_SESSION_KEY",
      "event_kind": "message",
      "scopes": ["task.resume", "message.send"]
    }
  ]
}
```

授权者由已认证管理入口填写，不接受请求体自行声称的授权者身份。`task.resume` 控制任务执行/恢复，`message.send` 控制受控外发，`tool.execute` 缩小已有工具审批和消息钩子/媒体预处理权限，`task.dispatch` 控制任务成员派发。未声明的范围不从消息文字、模型判断或运行令牌推导。自动任务的令牌只能续报原任务，不能另建一张无授权的卡。

## 撤回、恢复与可查记录

策略替换成功后旧版本失效，已有任务收到通知；失败写入不能放行。队列取出、重启恢复、派工和受控输出/工具许可时重验。恢复保留原决策，明确停止或撤回不会因换模型、换工作区而复活。管理员续验只创建关联原任务的新决策，不扩大其身份或范围；被明确撤回或移除规则的任务不能续验。

同一源事件受理为同一任务；角色和后端在分配记录中另记。任务内容和待恢复输入保存在私有日志中，公开事实不带原始私密输入。无卡片能力或不允许展示卡片的会话仅记录日志，成功不是消息已送达的证明；正常答复仍使用原平台入口。

工作区交回、任务线程副本和退回提示沿用原轮次授权，每个实际发送前检查 message.send。主动任务的线程副本绑定原任务，不选择会话中后来创建的卡。既有主角色唤醒定时器和退回后的心跳重跑不能携带任务授权，因此主动交回使用受控平台发送，不经这些入口创建无授权的新执行；普通显式任务保持原有流程。

该机制不构成操作系统沙箱。能收到执行前许可请求的后端才受许可重验约束；直接执行工具、只提供执行后通知的后端不能靠这层检查隔离系统权限。已经发出的不可撤销操作不声称回滚；结果不确定的受控操作保留记录，不自动重复。

源码与测试证据见[实现记录](implementation/751-proactive-authorization.md)。

验收分别检查普通聊天与推断任务：允许的普通聊天仍可回复，原门闸拒绝的消息仍不执行；observe 候选不创建主动任务、不启动主动执行者或发送主动确认。
