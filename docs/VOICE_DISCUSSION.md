# 电脑语音讨论

Issue #26在多伙伴选择入口之上增加一场有结束条件的讨论；不改变CLI的回答速度或Qwen合成方式。输入是2—3位已有伙伴与一个话题，输出是两轮发言和第一位伙伴的总结，反馈包括作者、阶段、原文、音频、播放状态及失败原因。

## 使用

按[MULTI_VOICE.md](MULTI_VOICE.md)准备显式配置与伙伴名单，运行voice.multi后打开`/discussion`。按勾选顺序发言：第一轮提出看法，第二轮回应已有观点，第一位最后总结共同点与分歧，共5—7段。首版键入话题；麦克风录题、口头点名和插话不在本版。

每段真实回答及音频就绪后播放。浏览器报告播放完成，或用户点击“跳过本段”，才会安排下一位。自动播放被浏览器阻止时点击“播放本段”；播放失败停留本段，可以重播或明确跳过，不自动跳过。页面只有一个播放器。刷新恢复当前讨论但不自动播放旧音频，也不再次发送整场请求。此版面向同一台电脑的单用户，不提供跨标签页音频所有权或多人并发主持。

“停止讨论”暂停本页播放并停止后续派发。已经发给CLI的当前任务仍可能执行；页面显示正在停止并占住入口，直至原回执收尾。它不等于取消模型任务。模型、合成、会话核对或关键记录失败会结束讨论，保留已有原文，不自动重发、不生成假总结。服务退出会中断观察，原任务执行结果须核对。

## 会话与记忆

讨论开始前逐位查询已有绑定，全部有效且空闲才接收。每轮再次核对开始时冻结的session/agent pair，并由桥接在会话锁内核对预期ID。Discord中切换会话后不能把后续发言误送到新会话；不支持严格恢复或没有具体会话编号的伙伴不能加入。会话可查询只说明绑定存在，远端CLI是否能恢复、有额度，须以实际轮次为准。

每位看到带作者、角色和阶段的本场前文；每条引用最多1100字，节选明确标记，完整回答仍在共享记录。原会话保留各自上下文，不把别人的观点冒充自己的经历。讨论提示明确只交流建议，没有额外授予修改文件、执行项目或派子Agent的权限；这是行为约定，沿用已有CLI权限，不构成新工具沙箱。

每个submitted/finished/playback事件带discussion_id、project、phase和round；另有开始、确认推进和结束事件。语音正文通过本地input回执返回，不重复发送到Discord。正常启动最多保留100场讨论元数据，满后拒绝新场；音频仍只有最近20轮，旧记录可读不代表旧音频可重播。重启后本进程讨论状态不恢复，长期文字证据在原共享JSONL。

## 模块合同

- `voice/discussion.py`只编排发言顺序、开始/推进/停止与归属；`VoiceService`负责单轮桥接、TTS及记录。共同使用submit_lock和discussion占位，单人入口与讨论互斥。
- POST `/api/discussion`接收`id/topic/projects/rounds:2`；同ID同内容返回原场，不同内容409。GET `/api/discussion/{id}`返回快照。
- POST `.../advance`接收`turn_id/outcome`；outcome为completed或skipped，completed须有播放完成上报。只接受当前ready轮，重复确认幂等，旧轮不能推进新轮。
- POST `.../stop`不取消已发送CLI任务。配置接口包含active_discussion/last_discussion以便刷新恢复。原本机Origin/token校验继续生效。
