# CNAS v1 · 板端素材包格式

`tools/pack_assets.py` 生成、固件侧读取。写这份文档是为了让读端只依赖这一个
文件就能实现，不需要再猜生成脚本的内部结构。

- 生成：`python3 tools/pack_assets.py --ffmpeg <path> --out build/assets.bin`
- 校验：`python3 -m unittest discover -s tests -p 'test_pack_assets.py'`
- 每个片段是一串**完整、独立可解码**的 466×466 baseline JPEG 帧，不是视频流。

## 布局

全部**小端序**，结构体无填充（`#pragma pack` 语义）。三段连续：头部 → 片段表 →
（每段的）帧索引表 → JPEG 数据。索引表都在 JPEG 数据之前，所以读端可以先只读
头部和索引，再按需 seek 取帧。

```
偏移 0
┌─────────────────────────────┐
│ header                      │  8 字节
├─────────────────────────────┤
│ segment table               │  23 × count 字节
├─────────────────────────────┤
│ frame index table(s)        │  8 × frames 字节，每段一块，按片段表顺序
├─────────────────────────────┤
│ JPEG bytes                  │  首尾相接
└─────────────────────────────┘
```

### header（8 字节）

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | `char[4]` | `magic` | 固定 `"CNAS"`（0x43 0x4E 0x41 0x53） |
| 4 | `uint16` | `version` | 当前为 `1` |
| 6 | `uint16` | `segment_count` | 片段数 |

### 片段表（每项 23 字节，紧接头部）

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | `char[16]` | `name` | ASCII，`\0` 右填充，最长 15 字节 |
| 16 | `uint8` | `fps` | 播放帧率，`0` 非法 |
| 17 | `uint16` | `frames` | 该片段帧数，`0` 非法 |
| 19 | `uint32` | `index_offset` | 该片段帧索引表在文件里的**绝对**偏移 |

第 `i` 项位置 = `8 + 23 * i`。`name` 是 `\0` 结尾的 C 字符串，读端用
`strncmp`/`memcmp` 匹配即可；**不保证**片段表有序，按名字查而不是按下标猜。

`fps` 是**逐段**的。当前这个包四段恰好同一个值，但读端不要写死——按每段自己
那项 `fps` 计时，否则以后哪段单独调帧率就会播错速。

### 帧索引表（每项 8 字节）

第 `i` 段第 `f` 帧的位置 = `index_offset + 8 * f`。

| 偏移 | 类型 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | `uint32` | `offset` | 该帧 JPEG 起始在文件里的**绝对**偏移 |
| 4 | `uint32` | `len` | JPEG 字节数，`0` 非法 |

帧是自包含的：从 `offset` 取 `len` 字节就是一张能直接喂给解码器的 JPEG，
不需要参考前后帧。

### JPEG 数据

- 尺寸 466×466，`RGB`，baseline（SOF0，**不是** progressive SOF2）；
- YUV420 采样（4:2:0），与 `benchmarks/jpeg` 里的 fixture 规格一致；
- 起始 `FF D8`，结束 `FF D9`。

## C 结构体参考

```c
#include <stdint.h>

#define CNAS_MAGIC "CNAS"
#define CNAS_VERSION 1
#define CNAS_NAME_LEN 16
#define CNAS_SCREEN 466

typedef struct __attribute__((packed)) {
    char     magic[4];      /* "CNAS" */
    uint16_t version;
    uint16_t segment_count;
} cnas_header_t;             /* 8 B */

typedef struct __attribute__((packed)) {
    char     name[CNAS_NAME_LEN];
    uint8_t  fps;
    uint16_t frames;
    uint32_t index_offset;
} cnas_segment_t;            /* 23 B */

typedef struct __attribute__((packed)) {
    uint32_t offset;
    uint32_t len;
} cnas_frame_t;              /* 8 B */
```

`_Static_assert(sizeof(cnas_segment_t) == 23, ...)` 值得加一条：这几个结构体
依赖 `packed`，编译器一旦插入填充，字段就会整体错位。

读端至少要做的检查（生成端已经保证，但落板后 Flash 损坏、烧错分区都会破坏它）：

1. `memcmp(magic, "CNAS", 4) == 0`，`version == 1`；
2. 片段表、索引表、每帧的 `offset + len` 都在分区容量内；
3. `fps != 0 && frames != 0`；
4. 每帧前两字节是 `FF D8`（JPEG SOI）。

## 每段的取帧区间

**四段都用网页同款的完整片段**，不再单独截子段。Flash 分区放大到 12 MiB
（打包预算 11 MiB）之后不必再省；`idle` 整段里有眨眼，首尾接不接得上跟网页
完全一致，比截子段更安全。

| 片段 | 板端取帧区间 | 时长 | 说明 |
| --- | --- | --- | --- |
| `idle` | 4.65s–9.90s（整段） | 5.25s | 网页同款，含眨眼 |
| `listening` | 0s–4.04s（整段） | 4.04s | 闭合循环 |
| `thinking` | 0s–3.96s（整段） | 3.96s | 闭合一圈 |
| `speaking` | 0s–4.04s（整段） | 4.04s | 闭合循环 |

起点、`scale`/`tx`/`ty` 仍来自 `source.html`，所以画面和网页圆屏一致。

**8MB Flash 的备用方案**：`--budget-mib 7 --board-range idle=4.65,7.15`，
idle 截成 2.5s 含眨眼子段，实测 6.49 MiB / 149 帧，装得下。

### 背景：idle 子段「有眨眼」与「首尾闭合」不可兼得（当前不用）

在 idle 原片里遍历 2.0~3.0 秒的所有候选区间（按 12fps 的帧格走），算每个候选
**首尾帧的平均像素差**，取最小的那个。差值越小，循环回接时越不跳。

    python3 tools/pack_assets.py --ffmpeg <path> --auto-idle-range

输出（gpt）：

    idle 自动选段：6.900s–9.650s（2.75s，首尾帧平均差 9.30 级，段内最大动作 8.14 级）
      注意：这一段几乎没有动作（眨眼峰一般 ≥12 级），待机画面会基本静止。

**但默认值不是这个区间。** 这版 idle 整段 4.65–9.90s 本身不是闭合循环：眨眼只在
4.8–5.3s 发生一次，之后就缓慢漂移。所以两个目标不可兼得：

| 区间 | 首尾差 | 段内最大动作 | 结果 |
| --- | --- | --- | --- |
| 4.65–7.15（**默认**） | 35.90 级 | 19.38 级 | 有完整眨眼，但循环回接会跳 |
| 6.90–9.65（首尾差最优） | 9.30 级 | 8.14 级 | 几乎静止，待机不动 |
| 5.07–7.07（含眨眼里最闭合） | 23.82 级 | 18.46 级 | 起点在眨眼中间，回接等于闭眼跳睁眼 |

2.0~3.0s 的候选里含眨眼的共 104 个，首尾差最小也要 23.82 级。所以默认取了
4.65–7.15：`source.html` 的起点、含完整一次眨眼、2.5s 也最省空间。代价是
首尾差 35.90 级——但这版素材网页上本来也是这么循环的，不是打包引入的。

下一版如果让美术出一段首尾闭合的 idle 循环，两个目标就能同时满足，
`--auto-idle-range` 也会自动给出可直接用的区间。

### 覆盖方式

    --board-range idle=6.9,9.65          # 只对板端生效，可重复
    --auto-idle-range                    # 重新搜索（较慢，约 5 秒）
    --full-length                        # 全部用整段，仅排查用，会超预算

## flash 包与 tf 包：格式一样，段数不一样

同一套 CNAS v1 容器，**读端不需要为两种包写两条路径**，只是片段表长短不同：

| 包 | 段数 | 片段名 | 说明 |
| --- | --- | --- | --- |
| `--profile flash` | 4（+2） | `idle` `listening` `thinking` `speaking`（+`offline` `error`） | 11 MiB 预算、Q80、12fps |
| `--profile tf` | 10（+2） | 上面四段 + `curious` `doze` `happy` `pout` `shy` `yawn` | 不设上限、Q89、12 或 24fps |

小动作片段**按角色实际有的来**，不是固定六个：

| 角色 | 小动作 | TF 包段数 |
| --- | --- | --- |
| `gpt` | `curious` `doze` `happy` `pout` `shy` `yawn` | 10 |
| `gemini` / `grok` | `doze` `happy` `shy` | 7 |

播放顺序和随机策略由固件决定，打包器只保证名字和内容。小动作只在 `idle`
状态下插播，这个逻辑不在素材里。**读端不能假设一定有 6 个**，要按名字查、
按实际段数遍历。

两份包都**按名字查片段**，读端不要假设段数或顺序。

## 断网 / 出错的静态状态图

`--status-dir` 会把 `<前缀>-offline.png` 和 `<前缀>-error.png` 各打成**一个独立
片段**，每段 **1 帧、`fps=1`**。固件在断网和出错时显示这两帧，不用等动画。

- 片段名固定是 `offline` 和 `error`，附录在两段状态片段之后；
- 图是 720×720 设计稿，**整幅缩放到 466×466**（LANCZOS），不套角色的
  `scale`/`tx`/`ty`——那是设计好的整屏画面，不是角色动画；
- 文件名前缀默认取角色目录名，G哥 的素材叫 `gge`（见 `STATUS_PREFIX`），
  不一样时用 `--status-prefix` 覆盖；
- 每张约 30 KiB（JPEG 后），两张合计约 63 KiB。

读端按名字查 `offline` / `error` 即可，`fps=1` 表示它本来就不是动画，
显示一帧后停住。**不传 `--status-dir` 时这两个片段不存在**，读端要能接受
片段表里没有它们（只有 4 段）。

## 预算与降级

默认总大小上限 **11 MiB**（`--budget-mib`），对应 assets 分区 12 MiB、留 1 MiB
余量。8MB Flash 的板子用 `--budget-mib 7`。生成脚本按固定阶梯尝试，取第一个
装得下的档：

1. `fps ≤ 12, Q80`（起始档）
2. `fps ≤ 12, Q75`
3. `fps ≤ 11, Q75`
4. `fps ≤ 10, Q75`（下限）

`Q75` 和 `10fps` 是**下限**，脚本不会为了塞进预算继续往下掉。到最低档还超预算
就**报错退出（退出码 2）并且不写文件**，同时在 stderr 打逐段大小，让人去决定
是提高预算、砍小动作还是缩短片段。没有 `--allow-over-budget` 之外的悄悄放宽路径。

## 与网页圆屏的关系

裁切参数**不复制**一份，而是直接读 `prototypes/device-ui/source.html` 的
`CHARACTER_CONFIG`（它同时是 `screen.js` 的构建源，见 `prototypes/device-ui/build.py`）。
网页改了 `scale`/`tx`/`ty`/`start`/`end`，重新打包就跟上，不会两边数字各自漂移。

换算方式：网页对视频元素做 `translate(tx%, ty%) scale(s)`，
`transform-origin: 50% 50%`，元素按 `object-fit: cover` 铺满圆屏，所以

```
screen = half + t + s * (elem - half)
```

取逆得到 466×466 画面在源视频里的取景框。`scale` 小于「刚好铺满」时取景框会
超出画面边缘，那块在网页上露出的是片段的 `bg` 底色——生成端用 `bg` 填满，
**不做夹紧**。夹紧会让整幅画面位移，例如 `thinking` 的 `ty=+6.2%` 会在顶部留约
22px 底色，夹掉之后人物和问号的位置就跟网页对不上。

## 片段名

| name | 来源 | 说明 |
| --- | --- | --- |
| `idle` | `clips.idle` | 待机 |
| `listening` | `clips.listening` | 倾听 |
| `thinking` | `clips.thinking_question` 或 `clips.thinking_calm` | 由 `--thinking` 决定，默认 `question` |
| `speaking` | `clips.speaking` | 说话 |
| `<小动作名>` | `idleVariants.*` | 待机随机小动作，如 `yawn`、`doze`、`curious` |

小动作的片段名就是它的 key，读端按名字挑，不要假设一定存在——`--extras 0`
时只有前四个。
