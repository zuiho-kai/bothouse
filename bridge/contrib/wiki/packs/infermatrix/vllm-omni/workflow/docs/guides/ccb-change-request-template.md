# vLLM-Omni CCB 需求变更申请模板

## 关键事实

- 源页：`knowledge/repos/vllm-omni/docs/guides/ccb-change-request-template.md`（InferMatrixCopilot@ecfb84d0）；type: guide；tags: vllm-omni, docs, planning；created: 2026-09-15；updated: 2026-09-15
- **何时使用**：已基线的 vLLM-Omni 需求需要通过 CCB 申请变更时，用本页确认变更类型、原需求基线、变更后描述、逐项变化点、工作量与交付时间影响均已明确。
- 本页模板与 [[rat-requirement-template]]（RAT 需求文档模板） 配套：CCB 变更必须挂在一条已评审通过的需求基线上，新需求的首次评审不在本页办理。使用时替换所有占位内容，并在评审完成后填写 CCB 评审结论。

### 模板

````markdown
### 变更名称

（示例：【xxLHS】日志归档需求规格与交付时间变更——AR2 日志保留期调整）

### 变更单信息

| 字段 | 内容 |
|---|---|
| 变更编号 | （示例：CCB-2026-013） |
| 提出人 / 提出日期 | （示例：张三，2026/09/15） |
| 关联需求 / 基线 | （示例：RAT「xx提供日志归档、监控指标采集功能」，0.28 版本需求基线） |
| 变更发起方 | （示例：客户 EI / 项目组 / 开发自识别） |

### 变更类型

（单选；同时涉及多种类型时以主导类型为准，其余影响在变化点逐项说明）

1. 需求新增（在已基线需求上追加 AR 或场景）
2. 需求修改（修改既有 AR 的描述、规格或验收标准）
3. 需求删除 / 裁剪（移除既有 AR 或场景）
4. 交付时间变更（Region、局点或商用时间调整）
5. 工作量 / 资源变更（人力管道或依赖团队工作量调整）
6. 规格 / 约束变更（性能 SLO、支持的卡型号、输入输出规格等）

（示例：需求修改 —— AR2 保留期规格调整）

### 原需求描述（基线版本）

（摘录变更前已评审通过的内容，保持与原 RAT 逐字一致；本节不得直接修改原描述）

【需求背景和价值】
【客户诉求】
【AR 列表与工作量】（示例：AR1 上报告警信息 -1 人月；AR2 日志滚动压缩与老化删除 -0.5 人月）
【交付时间】（示例：2024/12/30 乌兰一、贵阳 202 商用上线）
【需求规格和约束】

### 新需求描述（变更后版本）

（变更生效后的完整需求描述，结构与原 RAT 一致；评审通过后作为新基线）

【需求背景和价值】
【目标客户】
【客户诉求】
【AR 列表与工作量】
【交付时间】
【需求规格和约束】
【需求定位】（示例：商用）
【周边依赖】（示例：依赖 MindIE-SD xxx 版本 xxxx 特性）

### 变化点

（逐项列出，一项一行；每项必须给出影响分析和波及范围）

| # | 变更项 | 原内容 | 新内容 | 影响 / 波及范围 |
|---|---|---|---|---|
| 1 | （示例：AR2 保留期） | 日志保留 7 天 | 日志保留 30 天，增加磁盘水位告警 | runtime 日志模块新增清理策略；DWS 侧对接接口不变 |
| 2 | （示例：交付时间） | 2024/12/30 | 2025/01/15 | 贵阳 202 商用上线顺延，需客户确认 |

### 工作量变化

（示例：）

1. 原工作量：1.5 人月
2. 变更增加 / 减少：+0.5 人月（AR2 清理策略与水位告警）
3. 变更后总工作量：2.0 人月
4. 人力来源：（示例：0.28 版本人力管道追加 / 冲抵原管道内其他需求）

### 交付时间变化

（示例：乌兰一、贵阳 202 由 2024/12/30 调整为 2025/01/15；其余局点不变）

### 风险与回退

1. 风险：（示例：水位告警依赖 DWS 新接口，接口延期则 AR2 规格回退为保留 7 天）
2. 回退方案：（示例：功能开关默认关闭，关闭后行为与原基线一致）

### CCB 评审结论

（评审完成后填写。示例：CCB 2026/09/18 会议接纳该变更，AR2 按新规格执行，2.0 人月纳入 0.28 人力管道，交付时间按 2025/01/15 基线更新；拒绝或有条件接纳时必须写明条件与复审时间）
````
