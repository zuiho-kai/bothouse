# Wiki schema

这是一个个人 LLM wiki（Karpathy 模式）。原始资料是 Claude Code 的会话记录（`~/.claude/projects`）；本目录是由 LLM
提炼、维护的那一层。改这里的任何东西之前，先读本文件。

## 分层：自上而下读，够用就停

| 层 | 文件 | 放什么 | 预算（`bin/lint.py` 强制） |
|---|---|---|---|
| L0 索引 | `MEMORY.md` | 每个**域**一行，不放事实 | ≤ 8 个域（misc 另计），每行 ≤ 80 字符 |
| L1 域 | `<domain>/README.md` | 每个**主题**一行：讲什么 | ≤ 15 个主题，每行 ≤ 120 字符 |
| L2 主题 | `<domain>/<topic>.md` | 现状 + 关键事实 | ≤ 60 行，≤ 4000 字符 |
| L3 日志 | `log.md` | 带日期的历史、会话链接 | 只追加，默认不加载 |

回答「怎么连我的服务器」：MEMORY.md → `infra/README.md` → `infra/server.md`。回答「上次 X 是怎么做的」：
在 `log.md` 里 grep 这个主题，再打开列出的会话（比如用会话续接工具）。

## 主题页格式

```
---
name: <topic>
description: <一行：最常用的事实>
metadata:
  scope: <这页收什么、不收什么>
---
# <标题>
## 现状        当前状态（重写，不追加）
## 关键事实    主机、IP、路径、命令、配置、版本
## 决策与踩坑  决定、失败过的做法、用户的偏好和否决
## 待办        未完成的事
```
只用这四个 `##` 节（可以带日期后缀，如 `## 现状（2026-10-11）`）；空节省略。节名是固定的：`bin/lint.py`
按 `config.json` 里的 `language` 检查（本 schema 对应 `"zh"`；`"en"` 用 Current state / Key facts / Decisions & pitfalls /
Open items，见 `schema/CLAUDE.md`）。
一条 bullet 一个事实，每行 ≤ 300 字符；用嵌套 bullet 分组，不写长句。
Claude Code 的记忆系统写入时会在 `metadata` 下加 `node_type`/`originSessionId`/`modified`，这是正常的；
`scope` 也放在 `metadata` 下。用用户的语言写。

## 规则

- **写现状，不写流水账。** 主题页只写现在成立的事。被取代的事实直接删（历史在 git 和 log.md 里）。
  主题页上不列会话清单，那些放 log.md。
- **保留被推翻的决定。** 一个决定或判断被推翻时，决策与踩坑 留一行：
  `曾以为/曾选 X → 因 Y 改为 Z (YYYY-MM-DD)`，免得以后再被提出来。普通事实变化不用留这行。
- **会过时的事实带日期。** 可能过时的事实（运行中的服务、版本、外部状态、待办）带绝对日期 `(YYYY-MM-DD)`。
  稳定的事实（路径、偏好）不用。
- **索引和正文一致。** README 那一行、页面的 `description:` 都要和正文一致；谁改页面谁同步两处。
- **放置。** 先选域，再选 `scope:` 合适的主题。都不合适就新建主题。不要为了塞进无关内容而扩大某页的 scope。
- **新类别。** 新主题：随便建（登记到域 README）。找不到合适域的零散主题放 `misc/`。只有 ≥ 2 个相关主题时
  才新建域（通常从 misc/ 升上来），总数不超过 8；太薄的域要合并。每次新建/合并/改名/拆分都记进 log.md。
- **一个事实只住一页。** 每个事实只出现在 `scope:` 拥有它的那一页（在 scope 里写明，比如「X 的状态以本页为准」）。
  其他页面用 `[[name]]` 链接，不复述。写之前先 grep；已有页面拥有它，就改那一页并链接。
- **索引覆盖整个域。** MEMORY.md 的每一行要说出该域所有主题族。新加的主题那一行没覆盖到 → 同一轮里更新那一行。
  不要把主题放在一个读者按 MEMORY.md 找不过去的域里；移走，或者新建域。
- **改名要传遍。** 东西改名（主机、路径、项目）时，全库 grep 旧名，每处都改；旧名只保留一次，写成 `原 X`。
- **写结论，不写过程。** 实验/排错页只留结果、原因和支撑它的 2–3 个数字。逐步计时、试错记录放 log.md 或留在会话里。
- **页面上不写批注。** 页面陈述事实，不写作者怎么判断的。不要写「未见用户确认」「不声称…」「（用户告知）」这类话。
  未确认的提议写成一行待办（`是否 X：已提议，用户未答复`）；没有依据的说法删掉。`bin/lint.py` 会拦这些词。
- **接近预算（≥ 80%）→ 每周 LINT 提前拆分**（`bin/lint.py --warn` 列出这些页）。
- **超预算 → 拆分或压缩**，不要只是删有用的事实：把主题拆成子主题、拆分拥挤的域、把历史移到 log.md。
- **绝不写秘密。** 不写密码、token、私钥。只写它们存放在哪里（比如 `~/notes/secrets.md`）。输入里的 `[REDACTED]`
  原来是秘密。
- **log.md 条目格式**（追加在末尾）：
  ```
  ## [YYYY-MM-DD] ingest | <sid8> <会话标题>
  - <domain>/<topic>: <改了什么>
  ```
  其他流程用 `review`（夜间）、`lint`、`dream` 或 `restructure` 代替 `ingest`。

## 阅读摘要（论文/外部项目）

- 深读完一篇论文或一个外部项目（整篇论文，或读了多个文件、超过约 10 分钟），当场写进 `refs/`，不等 ingest；
  并行的其他终端读之前先在 wiki 里 `grep -r <arXiv id|owner/name>`。自己的仓库不写代码导读，照旧只记为什么和踩坑。
- `refs/` 是固定域，不受「新域需 ≥2 个主题」限制。一个项目或主题一页 `refs/<topic>.md`（如 `diffusion-refs`），
  每篇论文/每个仓库 6–10 行；用到它的页只放 `[[链接]]`。
- 每条以原样的 arXiv id 或仓库 `owner/name` 开头，方便 grep；外部仓库再标读时的 commit/版本和日期。
- 四节的放法：来源、问题、方法 3–5 条、关键数字、事实性局限 → `关键事实`；对我们的意义、结论、不用的理由 →
  `决策与踩坑`，结论标日期（论文不变，结论会变）。
- 摘要用于判断和定位：要改代码、引用具体数字或细节前，回原文读对应段落；上游 commit 变了只读 diff。

## 工具

- `bin/ingest.py` 把会话分层写进本 wiki（引擎和模型在 `config.json` 里配）：
  - 白天：SessionEnd hook + 每 30 分钟 `--pending`：快模型（默认 Haiku）写入关闭/空闲的会话，不做核对；
    写失败的批次由强一点的模型（默认 Sonnet）重做；被额度拒绝的批次等晚上。某个 run 持锁时关闭的会话进队列
    （`.ingest.queue`），由那个 run 接着处理。
  - 夜间，周一至周六 03:00 `--nightly`：夜间引擎写入白天剩下的，再对照会话记录复核自上次复核以来白天写入的每一段
    （脚本把白天的 ingest diff 一起给它；复核只改这些行）——改错、补漏、去重（`SOP_REVIEW`）。Codex 遇到容量错误时
    在 `codex_models` 里换模型续跑同一会话，再失败就换 `after_codex`。
  - 每周，周日 03:00 `--lint`：lint 引擎整理整个 wiki。
  - Dream：每晚在 nightly 或周 lint 之后，读上次 dream 以来用户说的话，维护 `misc/rule-candidates.md`
    （反复出现的纠正/偏好 → 规则候选，由用户决定；从不改 CLAUDE.md）。引文由脚本对照所引会话核对。
  所有引擎用同一套 SOP 提示（语言随 `language` 配置）（`SOP_*`：要求 / 规则 / SOP / 验收标准）；脚本自己验收（lint ok、每个会话一条新的
  `ingest|review | <sid8>` 日志、只动 wiki 页面、log.md 只追加、没有大量删除）。模型在 git worktree `.ingest-work`
  里改，从不碰本工作区；验收通过的提交 cherry-pick 到这里，配置了 `remote` 时再 push。
- `bin/lint.py`：结构检查（预算、frontmatter、孤儿页、允许的节、行长、批注用语）。有违规时退出码 1。
  `--warn`：接近预算的页面/域、没有对应页面的 `[[链接]]`。
