# Discord 任务帖子区

任务板上的每件 Discord 任务对应「任务」论坛中的一个帖子。任务板是唯一状态来源，帖子首楼随它更新；不需要再记住工作区在哪里或翻聊天记录。论坛权限具备时，新任务直接使用这个帖子，不再创建另一条消息线程。已经运行的旧线程保留。

标签按需要你处理的顺序排列，点击 Discord 的标签即可筛选：

| 标签 | 含义 |
| --- | --- |
| 🔴 等你拍板 | 正在等你的决定或答复；首楼第二行写要你做什么。 |
| 👀 待验收 | 已交回，正在等所列验收人核对。 |
| 📦 等发布 | 等待发布，是否已合并看首楼当前进度。 |
| ⚙️ 在做 | 负责人正在执行。 |
| ⏸️ 暂停 | 已暂停，原因见首楼；不会自动恢复。 |
| ✅ 完成 | 已收口，帖子按现有任务线程的归档等待设置归档。 |

首楼依次显示状态和负责人、需要你做的事（仅等待你时）、现在、目标和原话。工作区频道可点开；提问、汇报、暂停、继续、退回、合并、上线和完成等关键节点留在帖子里，逐步执行的流水保留在工作区。聊天频道收到一行指向帖子的通知。长问题不挤占目标；问题显示不完时，按提示查看下方最新回复。

任务从其他状态进入「等你拍板」时，如果任务板记录的派活人能确认为真人，会在帖子里提醒此人一次。派活人缺失或只有 AI 项目名时不猜人、不提醒；没有周期性催促。现有整点收口汇报会附上同一任务板中的「等你拍板 N 件」和论坛链接；为零时省略。

## 在帖子里回复

本批提供帖子展示与通知。帖子内答复、补充要求、暂停和重开属于第二批回话对接功能；在该批合并并安装前，请从原聊天频道或工作区入口回复。论坛说明也不会提前宣称已经能直接对话。

## 整体开关

在对应项目的配置段中设置 task_forum = false，可整体关闭论坛同步、提醒和收口计数，新任务继续使用原任务线程；已有帖子不删除。不设置时保持第一批默认开启的行为。修改配置后按既有配置加载流程生效。

机器人缺少管理频道、发帖或发送消息权限时，桥沿用现有权限提示，并继续原任务线程流程。恢复权限后后续任务可使用帖子。此功能只作用于 Discord，其他平台维持原来的入口。
