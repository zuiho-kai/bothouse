# Discord 任务帖子区

每个现有 Discord 类别各有一个「任务」论坛，同类别内所有聊天频道共用它；不同类别的任务分开。任务从哪个聊天频道发起，就在该频道所在类别的论坛开帖。已有同类别「任务」论坛会被复用，不会再建一个全服总论坛。

任务板是唯一状态来源，每件任务对应一个帖子，首楼随任务板更新。论坛权限具备时，新任务直接使用这个帖子，不再创建另一条消息线程；已经运行的旧线程保留。

没有归类的聊天频道，会收到先在 Discord 频道设置中移入现有类别的提示。任务板记录与普通聊天继续可用，归类后按正常同步开帖。类别由你选择，桥不会猜频道用途、自动搬频道或建立兜底论坛。

标签按需要你处理的顺序排列，点击 Discord 的标签即可筛选：

| 标签 | 含义 |
| --- | --- |
| 🔴 等你拍板 | 正在等你的决定或答复；首楼第二行写要你做什么。 |
| 👀 待验收 | 已交回，正在等所列验收人核对。 |
| 📦 等发布 | 等待发布，是否已合并看首楼当前进度。 |
| ⚙️ 在做 | 负责人正在执行。 |
| ⏸️ 暂停 | 已暂停，原因见首楼；不会自动恢复。 |
| ✅ 完成 | 已收口，帖子按现有任务线程的归档等待设置归档。 |

首楼依次显示状态和负责人、需要你做的事（仅等待你时）、现在、目标和原话。工作区频道可点开；提问、汇报、暂停、继续、退回、合并、上线和完成等关键节点留在帖子里，原来抄进任务线程的执行进度也留在同一个帖子里。聊天频道收到一行指向帖子的通知。长问题不挤占目标；问题显示不完时，按提示查看下方最新回复。

任务从其他状态进入「等你拍板」时，在帖子里 @ 一次等答复的人：任务板记录的派活人能确认为真人就提醒此人；派活人缺失或只是 AI 项目名（团队里通常如此）时，提醒桥的主人（admin_from 里第一个 ID）。没有周期性催促。现有整点任务收口汇报会附上当前类别的「等你拍板 N 件」和该类别论坛链接；为零时省略。类别中的帖子按实际所在论坛计数；旧全服论坛的待拍板帖按原来源聊天频道当前所在类别计入，并附原帖链接，不跨类别重复计数。

## 在帖子里回复

已登记任务帖中的真人回话会接回该任务的原聊天频道会话，答复仍发在原帖子里。同一类别的不同频道共享论坛，但不共享会话；桥依据保存的任务编号、帖子 ID、原聊天频道识别归属，不从标题推断。机器人和 webhook 发言不会触发任务动作（测试服用 test_webhook_people 点名的 webhook 按真人算，与其他入口一致），原有权限边界继续生效。

等你拍板时的回话用现有恢复入口接续；在做时的补充要求送到原任务。暂停、继续、关闭与返工由负责角色理解后调用现有命令，并在帖子里说明实际结果。已完成的任务在帖子里再回话算返工：board resume 先让桥把这件从「已关」拿回暂停（同编号），再用 ws-handoff --resume 接续，帖子随状态同步重开。

## 已有帖子和频道换类别

已有全服论坛及其中的任务帖保留，不删除或批量迁移。旧格式映射会从帖子的真实父论坛恢复并保存；旧帖仍可回复、更新标签和归档。频道移入另一个类别时，已有任务仍留在原帖子，新任务进入新类别的论坛；频道临时变成未归类也不影响已有帖子的回话。旧全服论坛帖的汇总使用保存的原来源频道查询当前类别，链接仍指向原帖；该类别尚未建立论坛也可显示旧帖。来源频道不存在或未归类时，不计入类别汇总，不建立兜底类别。

## 整体开关

在主角色项目的配置段中设置 task_forum = false，可整体关闭论坛同步、提醒和收口计数，新任务继续使用原任务线程；已有帖子不删除。不设置时保持第一批默认开启的行为。修改配置后按既有配置加载流程生效。

机器人缺少管理频道、发帖或发送消息权限时，桥沿用现有权限提示，并继续原任务线程流程。恢复权限后后续任务可使用帖子。此功能只作用于 Discord，其他平台维持原来的入口。
