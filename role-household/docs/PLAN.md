# 角色小家 计划书（草案 2026-10-18）

## 一句话
软件开源，靠卖硬件赚钱。一台主机加 n 台角色小机器人。每台机器人是一个二次元角色、一个音色。角色们在内置频道里用文字讨论，轮到谁，谁的机器人就把话说出来，同一时间只有一个在说。

## 已定的事（用户原话或已拍板）
- 软件开源、卖硬件，参照 HF 鸭子「开源但大家买成品」。
- 每个角色一台机器人，卖 1 + n 台；用会议发言锁保证同时只有一人说话。
- 用户不在乎回声：AI 不听机器人的声音，只读内置频道。
- 目标用户是会用 Claude Code 的极客，卖一体机。
- 每个角色可选模型，多用国产模型降成本（用户 2026-10-19）。
- 屏幕头可拆、可便携，下面接底座：固定座、HF 鸭子形身子、履带、步行机器人。
- 透明半球卡在头的正面，电路藏在底座里。
- 角色形象是二次元，由用户自己上传，平台不管角色内容。

## 架构
```
 用户（在内置频道打字发话题）
        │
 ┌──────▼──────────── 主机（Mac / 常开小主机）─────────────┐
 │  内置频道（类 Discord，文字）                            │
 │     ▲  ▲  ▲  每个角色 = 一个 Claude Code 会话 + 自己的 wiki│
 │  会议调度：发言锁（全局一把，先到先得，人说话就打断）     │
 │  TTS：按角色的音色把发言转成语音                           │
 │  设备网关：小智协议 WebSocket，推语音 + 表情                │
 └─────┼──────────┼──────────┼──────────────────────────────┘
       ▼          ▼          ▼
    机器人 A    机器人 B    机器人 C  （ESP32-S3 圆屏，小智固件改）
```
- 没到货前，用网页里的圆形「虚拟头」代替真机，软件先做。
- 真机复用小智开源固件（MIT），主机端只实现它协议里要用的一小部分；一台设备绑一个角色、各用各的音色，参照 xiaozhi-esp32-server。

## 进度表（软件、硬件两条线并行；日期是计划）
- 10-19~10-21｜软件：仓库、内置频道、3 个角色文字讨论、发言锁、网页虚拟头；先在 Mac 上跑｜硬件：三台板子已下单（无触摸、带触摸、带摄像头各一），10-20 到货｜验收：浏览器里三个头轮流出字，同时只有一个在说
- 10-22~10-25｜软件：每个角色单独配模型（国产模型为主）；每个角色接音色，虚拟头出声；量交棒间隔和冷场｜硬件：到货，三台都先刷原版小智确认能用｜验收：网页里三种声音轮流说
- 10-26~11-01｜软件：设备网关，三台真板连主机、各绑一个角色｜硬件：三台摆桌联调；带触摸那台试摸头互动，带摄像头那台的用途待用户定｜验收：三台真机轮流说话、做表情
- 11-02~11-08｜体验周：用户在桌上真用一周，对照一块屏放三个头像，找出多台实体怎样才更值（交棒、表情、摆位）｜验收：列出要改的体验点
- 11-09~11-22｜软件：用户上传角色图和音色、安装文档、开源发布｜硬件：35mm 透明半球干放试，3D 打印头壳和固定座，头壳一开始就留可拆接口；主机选型（Mac 之外的常开小主机）和外壳一起定｜验收：陌生人照文档能装起来
- 12 月以后｜鸭子、履带、步行底座
